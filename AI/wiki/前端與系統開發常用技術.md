# 前端與系統開發常用技術指南 (Developer Tools & Best Practices)

本頁面彙整了專案開發中常見的工具使用、核心機制與最佳實踐，涵蓋版本控制 (Git)、跨平台框架 (Electron)、Unix 腳本執行 (Shebang)、以及網路分發 (CDN)。

---

## 1. 版本控制系統：Git 新手實戰

**Git** 是一個分散式版本控制系統，如同專案的「時光機」與「儲存分身」。

### 核心工作流
```text
[工作目錄 (Working Dir)] ──(git add)──> [暫存區 (Staging Area)] ──(git commit)──> [本地儲存庫 (Local Repo)] ──(git push)──> [遠端 GitHub (Remote)]
```

- **第一步：配置身份**（全域設定）：
  ```bash
  git config --global user.name "您的名字"
  git config --global user.email "your_email@example.com"
  ```
- **第二步：初始化**：於資料夾內執行 `git init`，會建立一個隱藏的 `.git` 資料夾作為版本資料庫。
- **第三步：暫存與提交**：
  - 查看狀態：`git status`
  - 暫存變更：`git add .`（句點代表全部）
  - 提交存檔：`git commit -m "本次修改說明的備忘錄"`
- **第四步：分支管理 (Branching)**：
  - 建立分支：`git branch feature-login`
  - 切換分支：`git checkout feature-login`
  - 合併回主線：切回主線 `git checkout main` 後，執行 `git merge feature-login`。
- **第五步：防呆救援指令**：
  - 放棄單一檔案的未存檔修改：`git checkout -- <檔名>`
  - 強制退回到上一次 commit 狀態：`git reset --hard HEAD`（慎用）

> **延伸閱讀與交叉連結**：

## 2. 跨平台開發與環境規範

### Electron 框架
- **定位**：使用 HTML、CSS 和 JavaScript 構建跨平台桌面應用程式的開源框架。
- **原理**：將 Chromium 瀏覽器引擎與 Node.js 運行環境相結合，使網頁應用能直接擁有作業系統級別的存取權限（如讀寫本地檔案、調用作業系統 API）。

### Shebang (#!) 規範
- **定義**：在 Unix-like 系統（Linux, macOS）的腳本檔案第一行開頭的字元序列。
- **作用**：告訴系統應使用哪一個直譯器來執行該腳本。
- **最佳實踐**：
  - 執行 Bash 腳本：`#!/bin/bash` 或 `#!/usr/bin/env bash`
  - 執行 Node.js 腳本：`#!/usr/bin/env node`
  - 執行 Python 腳本：`#!/usr/bin/env python3`
  - *說明*：使用 `/usr/bin/env` 的好處是它會自動在使用者的系統環境變數 (`$PATH`) 中尋找直譯器，具備更好的跨平台移植性。

## 3. 專案輔助與網路分發

### CDN (內容傳遞網路)
- **原理**：在遍佈全球的伺服器節點上快取網站的靜態資源（如 JS, CSS, 圖片）。
- **作用**：當使用者造訪網站時，系統會自動導向距離最近的 CDN 節點，大幅減少主要伺服器負載並加速網頁載入速度。

### Snippets (程式碼片段)
- **定位**：預先定義好的常用代碼範本，通常可在編輯器（如 VS Code）中輸入簡寫並按下 `Tab` 鍵快速展開，可大幅提升編碼與文件撰寫效率。

### Slack 整合
- **應用**：利用 Webhooks 將系統警報、自動部署狀態或 Git 提交日誌自動推送至特定 Slack 頻道，實現團隊協作與 CI/CD 的自動化通知。

## 4. 資料庫入門：SQLite

**SQLite** 是全世界部署量最大、最廣泛使用的 SQL 資料庫引擎，幾乎每支 Android／iOS 裝置、Mac／Windows 系統與瀏覽器背後都在使用它。

- **核心特性**：**Local（本機）資料庫**，無 Client-Server 架構、不需架設伺服器、無需繁複設定；整個資料庫就是一個檔案，穩定可靠，適合中小型軟體。
- **常用命令列（`.` 開頭指令）**：`.open <檔名>` 開啟/建立資料庫檔案、`.tables` 列出所有表格、`.schema` 顯示表格架構、`.indexes` 顯示索引、`.mode columns` / `.headers on` 讓 SELECT 結果以整齊表格顯示、`.dump` 將整個資料庫內容轉存為可攜式 SQL 語句（可整包移植到另一個 SQLite 甚至 MySQL、Oracle）、`.shell` 直接呼叫系統指令。
- **限制**：不支援 `ALTER COLUMN`／`ADD CONSTRAINT`；對 Trigger 支援有限；View 為完全唯讀（Writing to VIEWs 不支援）；因為是單機檔案架構，沒有 `GRANT`/`REVOKE` 多使用者權限機制的概念。
- **與其他語言整合**：PHP、Python 皆內建 SQLite 函式庫，不需額外安裝即可使用（下一步可延伸學習 Python 的 `sqlite3` 套件）。

## 5. 通訊協作平台：Discord

**Discord**（2015 年上線）以文字、語音、直播為核心，最初鎖定電玩玩家，現已延伸至學習社群、創作者與企業內部協作，可與既有的 [[#3. 專案輔助與網路分發|Slack 整合]] 應用互相比較。

- **核心架構**：使用者可建立/加入「伺服器」，再細分成多個「頻道」（文字、語音、論壇、公告、舞台 5 種類型），並用「身分組（Role）」做逐頻道細緻權限控管——這是 LINE 群組／LINE 社群目前做不到的分眾管理深度。
- **與 LINE 的核心差異**：Discord 一般伺服器人數上限高達 2,500 萬人，原生支援多頻道分流與可疊加的身分組系統；LINE 群組僅 500 人且訊息全部混在同一聊天室。
- **免費版即可完整使用**：文字聊天、語音通話、建立伺服器完全免費且無則數/時間限制；付費 Nitro／Nitro Basic 方案主要差異在檔案上傳上限（20MB → 500MB）、跨伺服器表情貼圖與高畫質直播（4K/60fps）。
- **安全提醒**：Discord 提供雙重驗證（2FA）；官方唯一發放 Nitro 的方式是禮物贈送或兌換碼，不會透過陌生私訊發放（常見釣魚詐騙管道）。

## 6. JavaScript 全端基礎：Node.js 與 React

### Node.js（伺服器端 JavaScript 執行環境）
- **本質**：Node.js 是 JavaScript 的 **Runtime Environment**（非新程式語言），採用 Google Chrome 的 **V8 引擎**，讓 JavaScript 得以脫離瀏覽器、直接在作業系統或伺服器上執行，使前後端得以統一使用同一種語言。
- **與瀏覽器 JavaScript 的差異**：Node.js 沒有 DOM API（無 `document`/`window`）；模組系統預設支援 **CommonJS**（`require`/`module.exports`），也可透過副檔名 `.mjs` 或 `package.json` 設定 `"type": "module"` 改用瀏覽器慣用的 **ES Module**（`import`/`export`）。
- **三大內建模組**：`os`（作業系統資訊，如 CPU 架構）、`fs`（檔案系統讀寫，`writeFile`/`readFile`/`unlink`）、`http`（建立 HTTP 伺服器，`createServer` + `listen(port)`）。
- **npm（Node Package Manager）**：套件生態系中樞，`npm init` 建立 `package.json`，`npm install <套件名>` 安裝套件（記錄於 `dependencies` 欄位，實際檔案存於 `node_modules/`，不隨專案分享）；`npm install -g <套件名>` 安裝全域套件（如 **nodemon**，可監聽檔案變化自動重啟伺服器）；`package.json` 的 `scripts` 欄位可自訂 CLI 指令，透過 `npm run <指令名>` 執行。

### React（前端 UI 函式庫）
- **定位**：由 Facebook 於 2013 年開發的**函式庫（Library）**（非嚴格意義的框架），透過**元件（Component）**方式將網頁拆成獨立小單元，大幅降低大型網站的維護複雜度；屬於 **SPA（單頁式應用程式）**，初次載入後僅由 React 動態改寫同一個 HTML，無需每次換頁都向伺服器重新請求整份 HTML。
- **JSX**：讓你在 JavaScript 中直接寫 HTML 語法，經 Vite 等建構工具編譯為 JavaScript；每個元件只能回傳一個元素（可用空標籤 `<>...</>`／Fragment 包裹多個元素而不產生多餘 DOM 節點）；屬性命名如 `className`（取代 `class`）、`htmlFor`（取代 `for`），因為 `class`/`for` 是 JavaScript 保留字。
- **Props 與 State**：**Props** 讓資料由父元件單向傳遞給子元件（無法反向傳遞）；**State**（`useState`）則是元件內部可變資料——與一般變數不同，只有透過 `setState` 函式更新 state，React 才會重新渲染（re-render）對應的 HTML 元素。
- **開發工具鏈**：`npm create vite@latest` 是目前建立 React 專案最主流的方式（取代較舊的 `create-react-app`），開發伺服器具備即時熱更新（hot reload）。
