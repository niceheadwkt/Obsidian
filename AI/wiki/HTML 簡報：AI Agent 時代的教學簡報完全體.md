# HTML 簡報：AI Agent 時代的教學簡報完全體

三師爸 Sense Bar 2026-05-24 YouTube 直播（約 47 分鐘），現場用 Claude（Sonnet）搭配自訂 HTML 簡報技能，從查資料、生成簡報、換圖、加互動到打包成 Skill 一路實作。直播後公開技能 repo：`https://github.com/mathruffian-dot/claude-html-slide-builder`。逐字稿為語音辨識，專有名詞已依原意修正。

**一句話重點**：給 AI 看用 Markdown，給人看用 HTML

## 一、起因：HTML 要取代 Markdown？

Anthropic 一位工程師發文〈The Unreasonable Effectiveness of HTML〉，主張 AI Agent 的輸出應改用 HTML 而非 Markdown，引發大量討論（直播中提到約 4,400 萬瀏覽、8,200 讚、15,700 收藏）。講者的解讀是**看讀者是誰**：

| 讀者 | 格式 | 理由 |
|------|------|------|
| AI／程式 | Markdown | 語法精簡、省 token；早期 API 用量小，省下來划算 |
| 人類 | HTML | 資訊密度高、視覺豐富；超過約 100 行的長文件，可讀性遠優於 Markdown |

- **token 帳的變化**：現在 Agent 一跑動輒上百萬 token，HTML 多花的上下文只占一點點。
- **真正稀缺的是人的注意力**：Agent 做完會回報「做了什麼、接下來要你決定什麼」。人要讀懂回報才能做對決策；同時盯兩三個 Agent 時，讀吃力的 Markdown 會耗光腦力，最後只能回「照你的建議」。HTML 就是把可讀性留給人類。
- **反對與保留意見**：非技術使用者學習門檻較高；RAG 檢索場景仍以 Markdown 為主，HTML 勝在展示。

## 二、HTML 簡報的四大優勢

1. **資訊密度**：表格、SVG 向量圖表、程式碼、互動元件、版面配置與樣式表都能放進同一頁。
2. **視覺豐富度**：可用 AI 生圖取代 Emoji 圖標。
3. **互動能力**：可串資料庫、加按鈕、滑桿、拖拉。
4. **分享便利**：推上 GitHub 給一個網址，人用瀏覽器看、AI Agent 也讀得到內容；也可以不上網，整個資料夾存 USB 到任何電腦播放。

對照：傳統 PowerPoint／Google Slides 要加互動得靠即時反饋系統（IRS）軟體，會被工具綁住；NotebookLM 的圖片式簡報雖然漂亮，但很難再加功能、修改也慢。

## 三、實作一：用 AI 生圖取代 Emoji

講者認為 AI 簡報滿版 Emoji 有「廉價感」。示範用 Claude 串 OpenAI Image 2 API（最低畫質約新台幣 0.3 元一張），三種做法：

| 做法 | 說明 | 成本 |
|------|------|------|
| 直接生成插圖 | 每個 Emoji 各生一張圖縮小替換 | 最貴（四個圖標就是四張圖） |
| 生成整頁底圖 | 一頁一張背景圖疊在 HTML 後面，質感立刻提升 | 中 |
| 圖標總表＋裁切 | 生一張含所有扁平化圖標的總表，Agent 截圖裁切成獨立圖標再替換 | 最省，但要**明確告訴 Agent**「生一張總表再截圖」，它才會這樣做 |

- Agent 會自行判斷哪些頁要加底圖；要每頁都加就要明講。
- 現場翻車：圖標沒換到、沒去背、沒置中、忘了重新整理（Ctrl+F5）。都用自然語言請 Agent 修正。

## 四、實作二：在簡報裡加互動

- **文字雲**：第二頁加輸入框與文字雲，題目「你認為用 HTML 取代 Markdown 的理由為何？」，串 Firebase 資料庫；觀眾在自己的瀏覽器輸入，大家畫面即時出現。也可以做投票、選擇題、檢查點。
- **拖拉滑桿視覺化**：第六頁左邊放一篇 Markdown 原文，移動滑桿時逐步轉成好讀的 HTML 版面，現場展示「由不可讀到可讀」。
- **比動畫更可控**：傳統簡報動畫只能按下一步自動跑完；HTML 可用按鈕、滑桿、拖拉，讓講者控制要看到哪個階段，學科、非學科教學都適用。

## 五、打包成 Skill

做完一遍確認可行後，請 Claude 用 Anthropic 的 Skill Creator 把流程打包成 Skill：**給教材內容，由 AI 自行判斷**——

- 哪些頁要生成底圖（用畫圖技能）；
- 哪些 Emoji 要換成扁平化圖標（生總表再截圖）；
- 哪些頁要加互動（文字雲、選擇題、投票、檢查）；
- 哪些頁要做拖拉滑桿的視覺化展示。

產出後人還是要審核、微調。使用前提是另外裝好畫圖技能（講者「Claude AI 基本功」播放清單中有一集教學）。安裝方式：把 repo 網址貼給 Agent，它會自動安裝。

## 六、直播問答補充

- Skill 在 Claude Code 與 Codex 之間互通。
- Codex 也能畫圖：用訂閱額度在頁面端生成，免費但慢、限制多；用 API Key 較快但要付費，講者偏好 API。
- 全程用 Sonnet 示範仍用不完 20 美元方案額度；講者認為一般人 20 美元就夠用。

## 我可以怎麼用

- **給人看的 ERP 文件改用 HTML**：規格說明、需求單影響分析、上線說明、測試結果比對，這些要給主管或使用者看、要做決策的內容，請 Agent 直接輸出 HTML（表格、流程圖、前後對照），比 Markdown 好讀；我的影片製作工作坊講義已經是 HTML 版本。
- **給 AI 讀的維持 Markdown**：Wiki、CLAUDE.md、Skill、工作筆記都是給 Agent 讀與長期維護的，維持 Markdown 不必改。
- **Agent 回報太長時**：請它「整理成一頁 HTML 給我看」或發布成 Artifact，再決策；這正是「省人的注意力」的做法。
- **教學與研習**：上課簡報用 HTML 加文字雲或投票，免裝 IRS；離線場地就存 USB。
- **圖標用總表裁切法省成本**：需要多個圖標時，一張總表再裁切，比逐張生成便宜。
- **「先做順、再固化」的實例**：先手動做一遍、邊做邊修，確認可行再打包成 Skill（呼應 [[Claude Cowork 與 Agent Skill 實務]]、[[Claude＋Obsidian 第二大腦七步法]]）。
