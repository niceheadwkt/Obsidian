# Jev 與 System One 決策模型

**Jev** 是舊金山新創 **TypeSafe AI** 在 2026-09-15 發表的第一款模型。它**不生成文字**，只替軟體「做判斷」：輸入一段內容和問題，回傳程式可以直接使用的結構化結果，並附上每個決策的機率。發表後開發者湧入，官方 API 一度斷線。官網：https://typesafe.ai

> 來源：《數位時代》李先泰整理（2026-09-21，初稿為 AI 編撰），引用 TypeSafe 官方部落格與文件、TechCrunch、Sam Witteveen 實測影片等。

---

## 1. 定位：System One Model

- 名稱取自心理學家 Daniel Kahneman 的 **System 1**：快速、直覺、不需要長時間推理的思考。TypeSafe 稱這類模型為「System One Model」。
- 創辦人的觀點：LLM 在人類語言上已經強了四年，自動化卻沒跟上，因為「電腦講的是另一種語言」。程式要的是能直接分支、排序、路由的**值**，LLM 給的卻是還要再解析的文字，中間還可能有編造的內容。
- Sam Witteveen 的比喻：**「一個聽得懂人話的超強 if 判斷式」**。

### 三種回答方式

| 方式 | 說明 | 例子（客訴信「我被重複扣款了，請退款」） |
|---|---|---|
| **Choice**（選擇） | 從預設選項挑出最適合的一個 | 該轉給哪個部門 |
| **Score**（評分） | 依指定標準評分 | 退款需求有多強 |
| **機率判斷**（原文寫作 Noul） | 判斷一項敘述成立的機率 | 是否緊急 |

- 輸入是「**狀態＋問題**」。狀態可以是客服信、程式碼、AI Agent 的操作紀錄等非結構化內容。
- 一次可以問多題，各題**平行評估**，多問幾題幾乎不增加等待時間。
- 對語氣很敏銳：上面那句話的緊急度只有 7%，改成「現在就退！」後升到六、七成。
- **機率是模型在數學上算出的真實機率**；一般 LLM 回答的機率數字只是文字接龍拼出來的字串。對自動派單這類流程來說，這是比較可靠的判斷依據。

## 3. 三大應用

1. **取代 LLM 分類器**
   - Vercel 工程師原本用 GPT-5.6 Luna 審查指令安全性，改用 Jev 後快 5～18 倍，而且更準。
   - Bryo AI 技術長拿商業郵件分類和 Gemini 比較：Gemini 準確度微幅領先，但成本貴 10～20 倍。他認為「Jev 是唯一能回傳真實機率的模型」。
2. **監控其他 Agent**：用 Agent 監督 Agent，成本很快失控。改用 Jev 追蹤 LLM Agent 的操作軌跡、攔截越獄（Jailbreak）嘗試，防護成本比較合理。
3. **模型路由與即時分流**：處理任務前先用 Jev 判斷要不要動用昂貴的旗艦模型，取代以前「用 LLM 做初步判斷」的不划算做法。參見 [[生成式 AI 企業應用與成本經濟學#3. 語意路由 (Semantic Routing) 自動分流機制]]。

## 4. 上手方式（透過 AI 程式助理）

Jev 沒有聊天介面，最順手的用法是讓 [[Claude（Anthropic）|Claude]] Code 或 Codex 當中間人，由助理替你寫腳本、呼叫 Jev。

1. **開帳號**：到 TypeSafe 官網註冊，不用綁信用卡，送 5 美元測試額度。只依**輸入 Token** 計費，題目越長扣越多。
2. **安裝 Agent Skill**：
   ```bash
   npx skills add typesafe-ai/skills --skill typesafe-ai
   ```
   之後對助理說「使用 TypeSafe skill」就能喚醒，再到後台申請 API 金鑰交給助理設定。Skill 的概念參見 [[Claude Cowork 與 Agent Skill 實務]]。
3. **用白話交代任務**，文章提供的指令模板：
   > 請用 TypeSafe skill 幫我設計 Jev 的任務。我要整理［資料］，把每一筆分成［類別A／類別B／類別C／不確定］。規則：Jev 只負責判斷「語意」；算數、日期或字串比對請你（AI 助理）先算好再傳給 Jev。另外設定信心門檻，Jev 信心低於 0.6 的一律歸類為「待人工檢查」。動工前先給我看完整清單，我確認後再跑。

**分工原則**：Jev 只判斷語意；確定性的計算、日期、字串比對交給程式或助理先處理。

### 信心指數（Confidence）
- 表示 Jev 對自己的判斷**有多篤定**，**不是答對的機率**。選項很明確時會接近 1。
- 官方建議門檻先設保守一點，用自己的資料測過再微調。

### 範例任務
- LinkedIn 人脈分優先等級。
- Gmail 聯絡人分成「保留、待審、刪除」。
- 篩選學術論文「對一般人有沒有用」。

## 5. 使用注意

- **問題要拆小**：不要問「這份創業簡報好不好？」，要拆成「市場大不大？」「技術可不可行？」分開問，最後再由助理綜合評分。
- **不是魔法**：上面的成功案例，都是 AI 助理在背後寫了迷你網頁或 Python 腳本來執行。不用自己寫程式，但要有引導 AI 寫程式的耐心。
- 題目太短時信心會下降，同一題重跑可能有微小浮動。

## 6. TypeSafe AI 公司背景

- **創辦人 Diogo Almeida**：曾在 Google Brain、OpenAI 任職，是 2022 年 **InstructGPT 論文共同作者**，參與 RLHF（人類回饋強化學習），也就是催生 ChatGPT 的關鍵技術。2024 年離開 OpenAI 創業。
- **團隊**：技術長 Erik Gafni（曾創 DNA 定序 AI 公司 Ravel）、營運長 Sasha Sheng（前 Meta FAIR 研究工程師），其他成員多來自 Stripe、Airbnb、Docker。堅持每週五天進辦公室。融資資料參見原文所附的新聞稿（stealth 期間募得 4,000 萬美元）。
- **技術路線**：很早就押注**所有訓練資料自己生成**，公司一半編制是實驗室，專攻「統計上可理解的合成資料」。Almeida 認為這個決定比發明 RLHF 還重要。
- **命名**：取自**傑文斯悖論（Jevons Paradox）**，也就是商品變便宜、用量反而暴增。他賭的是 AI 成本大降後，世界會到處散布聰明、高效的微型軟體，而不是被單一超級 App 壟斷。
- **宣言**：「我們打造的是生產系統，而不是神。」
