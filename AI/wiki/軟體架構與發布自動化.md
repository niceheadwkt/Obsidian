# 軟體架構與發布自動化

本頁面專注於探討現代軟體開發的自動化發布管線（**CI/CD**）、雲端託管平台 **Netlify**，並結合開發效率工具 **PinClipboard** 進行剪貼簿的高效跨裝置同步。

---

## 1. CI/CD 持續整合與持續部署

**CI/CD** 是現代 DevOps 架構中非常核心的自動化流程：

*   **CI (Continuous Integration, 持續整合)**：
    *   **核心目標**：頻繁地將程式碼合併回主分支。當多位工程師提交程式碼時，系統會自動觸發建置 (Build) 與單元測試 (Unit Tests)，提早發現代碼衝突或 Bug。
*   **CD (Continuous Delivery / Deployment, 持續交付/持續部署)**：
    *   **持續交付**：自動測試與建置完成後，將可執行的版本送至類生產環境，由人工手動確認後一鍵部署。
    *   **持續部署**：更為激進，只要程式碼通過所有自動化測試，系統便會在背景**完全自動**發佈至正式生產環境，無須人工干預。
*   **常見 CI/CD 工具**：GitHub Actions、GitLab CI/CD、Jenkins、CircleCI。

---

## 2. 靜態網站託管平台：Netlify

**Netlify** 是一個專為前端工程師設計的雲端靜態網站託管與無伺服器 (Serverless) 平台：

*   **核心功能**：
    *   **Git 聯動發佈 (Git-based Workflow)**：連接 GitHub，當您執行 `git push` 後，Netlify 自動拉取最新代碼、執行編譯（如 React, Vue, Next.js），並部署上線。
    *   **分支預覽 (Branch Previews)**：為每個 PR (Pull Request) 自動生成獨立的測試網址，方便團隊審查。
    *   **Serverless Functions**：支援簡單的後端邏輯與 API 路由，無須維運實體伺服器。
    *   **全域 CDN 加速**：自動分發網頁至全球邊緣節點。

## 3. 開發效率工具：PinClipboard 與剪貼簿跨裝置同步

在進行 AI 對答、代碼片段整理或文件處理時，高頻率的複製貼上與跨平台文字共享是常見需求。**PinClipboard** 提供了一個輕量、區域網路直連的剪貼簿管理與同步方案。

### 3.1 核心功能頁籤
1.  **History (歷史紀錄)**：後台自動捕捉並記錄所有 `Ctrl + C` 複製的文字與圖片，防止歷史紀錄被沖刷掉。
2.  **Pin Board (圖釘看板)**：將常用的 AI 提示詞、萬用程式碼片段永久固定，雙擊即可重新複製。
3.  **Pin Folder (資料夾捷徑)**：直接拖入本機常用資料夾，雙擊即可開啟 Windows 檔案總管直達，省去層層尋找的繁瑣。

### 3.2 免 APP 區域網路跨平台直連 (電腦 $\leftrightarrow$ 手機)
*   **運作原理**：電腦端的 PinClipboard 會化身為區域網路內的小型網頁伺服器，並生成一個包含本地 IP (如 `http://192.168.x.x:port`) 的 QR Code。
*   **手機端操作**：手機與電腦連線至同一個 Wi-Fi 網路，掃描 QR Code 即可直接在手機瀏覽器打開「個人剪貼簿選單」，點擊即可複製並直接貼進手機端的 AI 對話框中。

## 4. 記憶體管理與 Ramageddon 防護

在本地運行大型 AI Agent、IDE 編輯器或進行大量 CI/CD 建置時，本機 RAM（隨機存取記憶體）容易被擠爆，導致系統卡死。
*   **Ramageddon (記憶體大決戰)**：是指本機資源被多個重度進程（如 Docker、vLLM、Node.js 龐大依賴）吃滿的災難狀態。
*   **防範機制**：
    1.  定時監控並殺死無效的背景 Python 殭屍進程。
    2.  限制本地 Agent (如 Ollama) 的併發線程數，並在不使用時主動釋放 GPU VRAM 與系統記憶體。
