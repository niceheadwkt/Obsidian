# SogaType 語音輸入 Windows 排錯紀錄

使用者 2026-09-20 在 Windows 11 Home（ASUS ROG Zephyrus G14，GA403WM）安裝台灣在地 AI 語音輸入工具 **SogaType v0.9.1**（搜咖科技 tv.SOGA 開發）時的排錯紀錄。排查方式包含反編譯 `SogaType.dll`、呼叫 Win32 與 CoreAudio API 檢測裝置狀態，以及檢查各程序的提權層級。

**一句話重點**：辨識成功卻沒打字，多半是 UIPI 擋了模擬貼上

## 一、SogaType 運作方式（排錯的關鍵）

| 環節 | 實作 | 對排錯的意義 |
|------|------|--------------|
| 收音 | .NET 8 程式，用 NAudio 的 WinMM `WaveInEvent`（舊式錄音介面） | 系統沒有可用的 WinMM 錄音裝置就完全不會錄 |
| 熱鍵 | Win32 `RegisterHotKey` | 收不到筆電多媒體鍵、會和系統熱鍵衝突 |
| 輸出 | 寫入剪貼簿 → `keybd_event` 模擬 Ctrl+V | 文字一定先在剪貼簿；貼不出來是「送按鍵」那一步失敗 |

## 二、四個坑與解法

### 坑一：按 F8 麥克風沒反應

- **檢測結果**：`waveInGetNumDevs()` 回傳 0；CoreAudio 查預設錄音裝置回 `0x80070490`（找不到）；內建「麥克風陣列（Realtek）」狀態為 `0x2`（`DEVICE_STATE_DISABLED`）。SogaType 開錄音時拋出 `NAudio.MmException: BadDeviceId`。
- **意思**：驅動正常、硬體也在，但邏輯音訊端點被軟體或系統策略停用。隱私權限開著也沒用。
- **端點四種狀態**：`0x1` 啟用、`0x2` 停用、`0x4` 硬體不存在、`0x8` 未插上。
- **可能肇因**：
  1. Windows 設定 → 系統 → 音效 → 麥克風內容頁誤按「不允許」（最常見）。
  2. ASUS 靜音鍵（Fn+F4）或「雙向 AI 降噪」建立虛擬麥克風後，原生端點沒被還原。
  3. Windows Update／Realtek 驅動更新時重新做端點遷移，內建麥克風被初始化成停用。
  4. 曾裝過 Typeless、NoType、VoiceType、Voicemeeter 或會議軟體，崩潰或卸載不完整留下停用端點。
  5. 現代待機（S0ix）喚醒時音訊晶片上電比 `Audiosrv` 慢，被誤判未就緒。
- **快速修法**：`Win+R` → `mmsys.cpl` → 錄音分頁 → 空白處右鍵勾「顯示已停用的裝置」→ 對麥克風陣列右鍵「啟用」。
- **當時的修法**：用腳本呼叫未公開的 `IPolicyConfig` 介面把端點設為可見並設為三種角色的預設裝置，之後 `waveInGetNumDevs()` 回到 1、1 秒錄音測試成功，重啟 SogaType 即可。

### 坑二：ROG 筆電實體 F8 無作用

F1～F12 預設由 ASUS Armoury Crate／Hotkey 當多媒體鍵，F8 是「調高亮度」，不送出 `VK_F8`。解法：按 `Fn+F8`、開 Fn Lock（或在 G-Helper／Armoury Crate 改成標準功能鍵），或在 SogaType 設定換熱鍵。

### 坑三：改用 `Ctrl+Space` 後出現「辨識中」卻沒字

剪貼簿裡其實已經有辨識結果。貼不出來的兩個原因：

- **游標不在輸入框**：模擬的 Ctrl+V 沒有目標。
- **熱鍵衝突**：`Ctrl+Space` 是 Windows 輸入法開關／中英切換，按兩次會讓輸入法狀態跳動、焦點被重置，後送的 Ctrl+V 被吞掉。

### 坑四：Notepad++ 能貼，管理員終端機不能貼（核心坑）

| 程序 | 是否以管理員執行 | 自動貼上 |
|------|------------------|----------|
| SogaType.exe | 否 | （發送端） |
| notepad++.exe | 否 | 成功 |
| WindowsTerminal.exe | **是** | **被擋** |

- **UIPI（使用者介面權限隔離）**：Windows Vista 起，一般權限（低完整性）程式**不能**對管理員權限（高完整性）視窗送出模擬按鍵或滑鼠訊號（`keybd_event`、`SendInput`、`WM_PASTE`），目的是防止背景惡意程式對管理員終端機下指令。被擋時**不會有任何錯誤訊息**。
- **解法**：
  - 臨時：看到「辨識中」消失後，自己按一次 Ctrl+V。
  - 根本：SogaType.exe 右鍵 → 內容 → 相容性 → 勾「以系統管理員身分執行此程式」，重啟後即可貼進管理員視窗。

## 三、附錄：F9 切換模式

F9 在「AI 校正（預設，修錯字、加標點、去贅詞）→ 中翻英 → 中翻日 → 中翻韓」間循環。設定中「翻譯語言」只勾需要的，例如只留英文，就變成「中文校正 ⇄ 英文翻譯」雙模式。

## 四、最佳實務

1. **熱鍵**：避開 `Ctrl+Space`，改用 **`Ctrl+Shift+Space`** 或搭配 Fn 的功能鍵。**不建議 `Alt+Space`**：它是 Windows 視窗系統選單，放開後焦點可能跑到選單，模擬的 Ctrl+V 會貼空（見 [[NoType 語音輸入專案分析與演進建議]]）。

> [!NOTE] 衝突已解決（2026-11-23）
> 原紀錄曾把 `Alt+Space` 列為可選熱鍵，與 NoType 建議書衝突。使用者決定統一採 `Ctrl+Shift+Space`，`Alt+Space` 標為不建議（未實測 SogaType 按一下開關模式是否也會貼空）。

2. **權限**：常在管理員終端機、PowerShell 或高權限 IDE 用語音輸入，就讓 SogaType 也以管理員執行。
3. **輸入節奏**：先點目標輸入框、確認游標在閃 → 按熱鍵（聆聽中）→ 說話 → 再按熱鍵（辨識中）→ 等約 1 秒自動貼上。

## 我可以怎麼用

- **語音輸入 Claude Code 時**：如果終端機是用系統管理員身分開的，SogaType 一般權限會貼不進去；平常盡量用一般權限開終端機，必要時才提權，或讓 SogaType 同步提權。語音轉出的錯字則交給全域規則的「語音輸入文字正規化」處理（見 [[AI Agent 實戰與 MCP 伺服器整合]]）。
- **UIPI 也適用其他自動化工具**：AutoHotkey、ERP 畫面擷取、RPA 或任何「模擬按鍵／滑鼠」的腳本，對管理員視窗都會無聲失效；排錯時先比對雙方的提權狀態。
- **「文字在剪貼簿但沒出現」的排錯順序**：先看剪貼簿 → 再看游標焦點 → 再看熱鍵衝突 → 最後看權限隔離。這個由外而內的順序也適用其他「看起來沒反應」的工具。
- **麥克風突然失效**：先開 `mmsys.cpl` 看是否被停用，再懷疑 App；換裝或卸載其他語音工具後特別容易發生。
- **給 AI 排錯的方式**：本次讓 Agent 直接呼叫系統 API、反編譯 DLL 找出輸出機制，比反覆重裝有效；遇到黑箱工具可以照這個方式請 Agent 先查「它怎麼做」。
