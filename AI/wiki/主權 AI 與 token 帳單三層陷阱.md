# 主權 AI 與 token 帳單三層陷阱

《數位時代》未來商務陳祈安整理（2026-10-13，初稿為 AI 編撰），內容為 Podcast〈數位關鍵字 EP250〉（2026-07-25 上架）中，《數位時代》創新長黃亮崢與 APMIC（亞太智能機器）創辦人暨執行長吳柏翰的對談。APMIC 負責台灣金融大語言模型（FinLLM）的調校，並自研 240 億參數的 ACE-1 模型。文中價格、評測數字以 2026-07 時點為準，且為業者自身說法。

**一句話重點**：敏感工作用地端小模型，守住資料、成本與流程

> 來源：https://fc.bnext.com.tw/articles/view/4974

---

## 一、背景：帳單失控與供應商風險

- APMIC 常聽到客戶「1 年的雲端 token 預算，3 個月就花光」；Uber 技術長也證實，大量導入 Claude Code 等 AI 寫程式工具後，2026 全年預算 4 個月就用罄。
- 政策面：行政院以教育、醫療、金融、司法為主權 AI 示範場景，「AI 新十大建設」2025～2028 年預估投入約 1,366 億元；法務部 2026～2028 年分三階段推動法務專屬大型語言模型。

## 二、主權 AI 的同心圓

| 層次 | 重點 |
| --- | --- |
| 國家主權（最外圈） | 模型懂我們的語言、歷史敘事與民主價值；算力中心在自己領土上 |
| 產業主權（中間） | 特定行業的合規需求，例如金融模型不能引用美國法規回答台灣銀行問題 |
| 企業主權（最內圈） | 資料不出門、成本可預測、不被單一供應商綁死 |

- 兩年下來，真正能全端自主的大概只有美國和中國；CNAS 追蹤的主權 AI 專案逾六成有外國夥伴。**主權不是完全獨立，而是在依賴與自主之間找平衡。**
- 台灣不和美、中在模型層正面對決：基座可以用開源、算力可以國際合作，但產業知識、法規邏輯與文化理解要自己掌握。

## 三、token 帳單的三層陷阱

1. **長文本懲罰**：受 HBM 限制，上下文超過一定長度，輸入計價多 1～2 倍；企業動輒處理幾萬字的合約、法規。
2. **輸出比輸入貴**：一般是 4～6 倍，寫報告、做深度分析的帳就高很多。
3. **推理的隱形稅**：推理模型先跑一段推理，用掉多少 token 看不到、無法預估，帳單照算。

- 成本比較（業者實測）：每個 AI 代理每日約一億 token，GPT-5.5 每百萬 token 約新台幣 450 元；ACE-1 以 NVFP4 精度地端部署、攤提軟硬體後約 83 元，節省逾 80%。
- **財務主權**：價格與升級時程由別人說了算。企業至少要守住三種控制權：

| 控制權 | 意義 |
| --- | --- |
| 資料絕對權 | 資料不離開你的掌握 |
| 模型自主權 | 不會因供應商一句「關了」就用不到 |
| 流程控制權 | 工作流程不因 API 改版就斷掉 |

少了這三種控制權，花半年做完需求訪談、導入、驗測與提示詞調校，供應商一紙公告停用模型就得整個重來。

## 四、小模型路線：最理解你的模型

- ACE-1 以 Google 開放權重模型 Gemma 為基座，用**知識蒸餾**把大模型能力壓進 240 億參數，再以 NVFP4 量化讓記憶體需求降 50%、精準度下降控制在 2% 以內。數發部 AI 評測中心（AIEC）評測綜合排名全球第五，價值觀題滿分。
- 比喻：大模型像百科全書，什麼都有但查起來慢又貴；小模型像行業實戰手冊，在擅長領域更快、更便宜、更精準。**主權 AI 不一定是最大的模型，而是最理解你的模型。**
- 開放權重模型載到自己機器上就是自己的；基座像建築地基，水泥可以換品牌（Gemma、Llama、Nemotron），上面的法規、法律邏輯與語境才是不可替代的資產。
- **知識分層、成本分流**：高敏感、需精確合規的工作交給地端小模型，通用、非敏感的繼續用雲端。有客戶查出近 60% 的 token 是員工在問中午吃什麼，地端小模型搭配 MCP 就能處理。

## 五、金融模型如何兼顧資料不出門與避免幻覺

- **產業公版模型**：放各家共通的法規、合規與情境資料，送進各家銀行後「讓模型去找資料，而不是資料送到模型」，各家再自行微調，資料不出門。
- **RAG 切塊的風險**：嵌入模型長度頂多約 32K，文件得先切塊；100 多頁的合約，第 20 頁財務比率符合授信條件、第 120 頁卻有例外排除條款，切錯就會漏讀。對策：
  1. **少切碎**：用 128K 甚至百萬 token 的上下文一次讀進去；超出時讓多個 Agent 分段，但每個 Agent 吃進去的都是完整長文本。
  2. **情境微調**：與其把提示詞調到上萬行讓 Agent 越來越慢，不如讓模型開工前就內建邏輯。例：未微調的開源模型呼叫 MCP 失誤率近 70～80%，微調後教它按步驟做，降到不到 10%。
- 金融場景的思考順序不同：先判斷提問者條件（30 歲與 70 歲的貸款方案不同），再判斷合規與風險，最後才整合答案。幻覺無法百分之百消除，但能大幅降低。

## 六、誰出錢與「工廠或宮殿」

- FinLLM 由 20 家金融機構集資分攤；法務模型由政府出資、再用訂閱制回收。理想是混合：先由政府或產業聯盟建模型與評測標準，再交給民間微調商用。
- Kevin Xu 的質疑：主權 AI 是生產 token 的「工廠」，還是沒人用的「宮殿」？Gartner 2025 年預測，**超過 40% 的 AI 代理專案將在 2027 年底前被取消**；有沒有紀律地做，決定是工廠還是宮殿。

## 七、企業決策者的第一步

1. **盤點**：算清雲端 API 費用、開發維護與人力成本；很多企業不知道每天燒多少 token，因為費用散在不同部門與專案。
2. **辨識紅線**：競爭力資料、公司知識資產、金融交易、醫療紀錄、法律文件若還在雲端跑來跑去，風險不只是成本，還有合規。
3. **選一個場景先導入**：挑痛點最大、資料最敏感的場景，用地端小模型跑跑看，不要想一步到位。

## 我可以怎麼用

- **ERP 資料是紅線資料**：正式機的交易、客戶、人事資料不應進入公有雲對話；查詢依 zpq 規範唯讀、只摘要必要結果，個資欄位不查。評估 AI 方案時，先用「資料絕對權、模型自主權、流程控制權」三項檢查。
- **盤點 token 花費**：整理部門或個人在 Claude、ChatGPT 等工具的用量與費用，找出哪些是可以分流給便宜或地端模型的日常問答，哪些是值得用頂級模型的規格設計與除錯。
- **規格書、合約不要只靠 RAG 切塊**：ERP 規格書或需求單的例外條款常藏在後段；給 AI 讀時盡量整份給、或分段但每段完整，並要求它列出例外與排除條件。
- **流程控制權**：skill、CLAUDE.md、知識庫都是本機 Markdown 檔，換模型或換工具也帶得走，這正是守住流程控制權的做法（呼應 [[Claude＋Obsidian 第二大腦七步法]]）。
- **導入 AI 代理專案時記得「工廠或宮殿」**：先選一個每天都會用、能量化成效的場景，避免做完沒人用。
- **帳單失控的另一個來源：憑證被盜**：除了正常用量，雲端 AI API 被盜用也會在一小時內燒掉數萬元，且預算提醒只通知不停機；設定支出上限、定期檢查服務帳號，見 [[假冒 Claude Code 官網木馬與雲端帳單盜刷事件]]。
