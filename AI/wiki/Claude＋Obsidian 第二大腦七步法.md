# Claude＋Obsidian 第二大腦七步法

整理自 Fanko AI 範式 YouTube 影片〈Claude＋Obsidian 第二大腦教學｜零基礎 7 步，讓 AI 從陌生人變成最懂你的同事〉（2026-11-17，https://www.youtube.com/watch?v=Vmrtckvc0DQ ）。作者從空白的 Obsidian 知識庫開始，用 [[Claude（Anthropic）|Claude]] 桌面版搭出一個 AI 每次開工都先看目錄、會自己整理收集箱、每週自己長大的知識庫，全程不寫程式。七步的順序參考 Grace Leung〈How I'd Use Claude If I Started Today〉，第七步呼應 Karpathy 的 LLM Wiki（見 [[個人知識管理系統構築]]）。

**一句話重點**：讓 AI 先讀你的知識庫，越用越懂你

> 操作畫面為 2026-11 的 Claude 桌面版與 Obsidian；讀寫本機資料夾與排程需 Claude Pro 以上方案，Obsidian 免費功能即可。

---

## 一、核心觀點：差距在「AI 懂不懂你」

- 高手與一般人用 AI 的差距只有一件事：AI 懂不懂你。新功能每月在變，但 AI 對你的理解與答案品質會越累積越精準，這就是**複利**。
- 做完七步會得到三樣東西：
  1. 一張 AI 每次開工先看的目錄（路由表）。
  2. 一個把好文章收進來、自動連到舊筆記的流程。
  3. 一個每週自己長大的知識庫。
- 分工：Claude 內建記憶記「你」；知識庫記「你的工作」。知識庫是本機檔案，換成 Codex 等其他工具也帶得走。

## 二、七步總覽

| 步驟 | 名稱 | 目的 | 關鍵做法 |
| --- | --- | --- | --- |
| 1 | 路由表 | 讓它認得你 | 讓 Claude 反過來訪問你，產出一頁以內的 CLAUDE.md |
| 2 | 入口 | 讓資料進得來 | 桌面版指定知識庫資料夾＋Obsidian Web Clipper |
| 3 | 入庫 | 把整理做法固化 | 三篇手動調整後做成「入庫」Skill＋評分標準 |
| 4 | 地圖 | 讓知識庫有出口 | 用 Artifacts 做「這週該回看哪幾篇」看板 |
| 5 | 品味 | 讓它寫得像你 | 定三種筆記模板；它出三版、你拍板 |
| 6 | 例行 | 讓它自己長 | 排程：每晚整理收集箱、每週一寫更新日誌 |
| 7 | 客製 | 做出專屬工具 | Claude Code 做 Obsidian 外掛、`/insights` 回頭檢討 |

## 三、各步驟要點

### 1. 路由表：讓 Claude 反過來訪問你
- 比喻：每天早上會失憶的聰明新同事，路由表是貼在他桌上的便利貼——我是誰、在做什麼、資料放哪、討厭什麼。
- 不要自己寫，給它這句：「一直問我問題，一次問一個，直到你完全懂我是誰、做什麼工作、喜歡什麼樣的格式、最討厭什麼，再幫我寫成一張路由表，不要超過一頁。」（同 grill-me 的思路，見 [[Claude Cowork 與 Agent Skill 實務]]）
- 最有價值的一題：「AI 什麼時候該先問你、什麼時候該直接做？」→ 寫成路由表裡的**決策規則**。
- 存成知識庫最外層的筆記，Code 分頁開啟該資料夾就會自動讀取。
- **路由表一定要短、只寫入口**：Code 分頁右側的 Context 卡顯示，還沒打字就被記憶、指令、技能占掉一塊；桌面越擠越容易忘、額度也燒得越快。內容放筆記，要用時再讀（參見 [[Claude 系統優化與 Token 節省指南]]）。

### 2. 入口：資料夾與 Web Clipper
- 入口一：桌面版選擇知識庫資料夾，Claude 直接讀寫，不再當複製貼上的搬運工；它只碰你指定的資料夾。
- 入口二：安裝 Obsidian 官方 **Web Clipper**（認明發行者 Obsidian.md，Firefox 有名字相近的非官方版），範本的 Note location 改成「收集箱」，一鍵剪存並自動填好標題、來源、日期。
- 坑：英文文章剪存前要**關閉瀏覽器自動翻譯**（實例：agent 被翻成「代理商」），翻譯交給 Claude。
- 連接器（Gmail、Google 雲端硬碟）不要一次全接，先接工作真正在用的那一個。

### 3. 入庫：把整理流程做成 Skill（全片最關鍵）
- Skill 是寫給 AI 的工作說明書：**路由表告訴它要什麼，Skill 告訴它怎麼做**。
- 從已做順的流程開始，提示詞三件事：一句話重點＋三個要點＋原文連結；找出相關舊筆記並加雙向連結；和我以前看法衝突的標出來（只標出、不下結論）。
- 前幾篇在同一對話逐次糾正，例如「一句話重點壓到 30 字內」、「第二個要點太空，沒寫是哪 5 種」。
- 三篇做完後，**在同一個對話**要求「把這套做法變成叫『入庫』的 Skill」，因為它已看過你怎麼改，說明書會比你自己想的準。
- 加**評分標準**並自評、未過自改：每篇有來源、至少連一篇舊筆記、一句話重點不超過 30 字。作者的 Claude 甚至寫了小程式來檢查，理由是知識庫裡有篇筆記寫著「AI 給自己打分一定會虛高」。
- Skill 名稱只能用英文（ruku），但說「入庫」也認得；平時只占一行名稱與說明，用到才載入，所以流程越存越多、桌面也不擠。

### 4. 地圖：Artifacts 小看板
- 做看板前先問：**這張地圖要幫我做什麼決定？**避免什麼都放、什麼都看不出來。
- 目標若是「這週該回看哪幾篇」，只需：本週收進幾篇、整理了幾篇、被連最多的是哪篇、還卡在收集箱的有哪些。被連最多的，大概率就是你這陣子真正在想的事。
- 看板是**一次性快照**，自己讀不到本機檔案，要最新版得請 Claude 重讀重畫。

### 5. 品味：三種筆記模板
- AI 幾秒就能寫出筆記，難的是知道什麼叫好；Claude 預設寫「平均值」，分段、標題、重點位置會臨場發揮。
- 定三種模板：一般筆記、人物／客戶資料頁、概念解釋頁（作者另有英文影片入庫專用）。
- 兩個方法：
  1. 給它幾篇你覺得寫得好的筆記，讓它歸納成規則，你再補漏（作者補了「每篇最後要有一行『我可以怎麼用』」）。
  2. 每次要它給**三個版本**並排，你挑一個再改——它出選項，你拍板。
- 回到入庫 Skill 補一句「以後整理都照這三種模板」。

### 6. 例行：排程讓它不靠你也在做事
- 排程在 Code 分頁設定。排之前先問：「**這個排程可能會出什麼問題？**」（收集箱是空的、抓不到全文……）作者實測，它列的第一條就是「沒跑，而且沒人知道」。
- 像電鍋預約：電腦醒著、Claude 開著才會跑；錯過時會在下次開機補跑最近一次。時間要排在電腦通常開著的時段。
- 只排你真的會看的，排越多只代表要回顧的越多。
- 兩個排程：
  1. 每晚 9 點用入庫 Skill 整理收集箱，**一定要留摘要**（幾篇、連到哪些、有無失敗）；沒事也要回報「0 篇」，才知道有在跑。
  2. 每週一早上寫上週更新日誌（新增什麼、被連最多、有無與舊看法衝突），穩定後存成「每週更新日誌」Skill。

### 7. 客製：Claude Code 做專屬工具
- Karpathy 的 LLM Wiki：AI 持續維護整套互相連結的筆記，你負責看、它負責寫；做完前六步其實已在這條路上。
- Code 分頁用白話描述需求即可，例如輸入客戶名稱列出所有相關筆記、月底產出可直接交主管的月報。
- 作者實作「查人」Obsidian 外掛：第一次打開一片空白，持續描述現象（「連提示字都沒出現」）後，第二次找到真正原因修好。
- `/insights`：回頭檢討最近 40 個對話，整理成五條「跟我共事的規矩」寫回路由表，同一個錯不犯第二次。
- 動手前先要它訪問你、給計畫：「一直問我問題，直到你完全懂我要什麼，再給我看計畫。」
- 前六步夠用就先不用推進第七步。

## 四、可直接套用的提示詞

| 時機 | 提示詞 |
| --- | --- |
| 建路由表 | 一直問我問題，一次問一個，直到你完全懂我是誰、做什麼工作、喜歡什麼樣的格式、最討厭什麼，再幫我寫成一張路由表，不要超過一頁。 |
| 固化 Skill | 把剛才這套做法變成一個叫「入庫」的 Skill，再加一份評分標準，每次做完先自己打分，沒過的就自己改。 |
| 套用模板 | 以後整理都照這三種模板。 |
| 排程前 | 這個排程可能會出什麼問題？ |
| 動手做工具前 | 一直問我問題，直到你完全懂我要什麼，再給我看計畫。 |

## 我可以怎麼用

本知識庫已採用 LLM Wiki 架構，對照七步的進度：

| 步驟 | 本知識庫現況 | 下一步 |
| --- | --- | --- |
| 1 路由表 | 根目錄 `CLAUDE.md`＋`AI/schema.md` | 全域 CLAUDE.md 的 zpq 查詢規則在 Obsidian 也會載入，可移到 ERP skill，讓路由表只寫入口 |
| 2 入口 | Web Clipper 剪存到 `AI/raw/` | 英文文章剪存前關閉自動翻譯 |
| 3 入庫 | 2026-11-18 建立 `wiki-ingest` skill 與 `wiki_tool.py check` 評分腳本 | 被糾正時把規則寫回 SKILL.md |
| 4 地圖 | `AI/dashboard.html` 已存在 | 改成只回答「這週該回看哪幾篇」，可用 `wiki_tool.py hubs` 取數 |
| 5 品味 | 已規定新頁要有一句話重點與本段落 | 為 concept／entity 頁另定模板，用「三個版本」法挑選 |
| 6 例行 | 尚未設定 | 用 Claude 桌面版排程每晚跑入庫、每週寫更新日誌，並強制回報摘要 |
| 7 客製 | 2026-11-18 建立 `wiki-lint` 健檢 | 定期 `/insights` 檢討後寫回 CLAUDE.md |

ERP 工作也能套用同一套：把正式機查詢、CVS 提交等流程先手動做順，再固化成 skill，並寫進檢查標準，讓 AI 交件前先自己檢查過。
