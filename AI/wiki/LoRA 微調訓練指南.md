# LoRA 微調訓練指南

整理 LoRA（Low-Rank Adaptation，低秩適應）在**大型語言模型**（Llama 3、Qwen、Mistral 等）與**擴散生圖模型**（SD 1.5、SDXL、Flux）上的原理、資料準備、工具與參數建議。來源為無作者、無日期的技術整理文件；參數為一般建議值，實際仍要依模型與資料調整。

**一句話重點**：凍結原模型只訓練外掛小矩陣，家用顯卡就能微調

## 一、LoRA 是什麼

傳統微調要更新模型全部參數（數十億到數百億個權重），需要極大的顯示記憶體與儲存空間。LoRA 的做法：

- **凍結**原本預訓練模型的權重 $W_0$；
- 在特定層（如 Self-Attention）外掛兩個小型**低秩矩陣** $A$、$B$ 來訓練；
- 權重更新量 $\Delta W = B \times A$，實際輸出 $W = W_0 + \Delta W$。

| 優勢 | 說明 |
|------|------|
| 硬體需求低 | 只算少量參數，RTX 3090／4090 等消費級顯卡可完成多數訓練 |
| 檔案小 | 基礎模型數 GB 到數十 GB，LoRA 通常只有 10～500 MB |
| 可組合 | 同一個基礎模型可隨時切換或疊加多個 LoRA（例：基礎模型＋領域知識 LoRA＋語氣 LoRA） |

## 二、語言模型（LLM）的 LoRA

**用途**：調整對話風格、特定領域知識、指令遵從、固定格式輸出（JSON、程式碼）。

**資料格式**（`.json`／`.jsonl`）：
- **指令格式**：`instruction`、`input`、`output` 三欄，一筆一問一答。
- **多輪對話格式**（ShareGPT／Messages）：`messages` 陣列，依序放 `system`、`user`、`assistant` 的內容。

**訓練工具**：

| 工具 | 特色 |
|------|------|
| Unsloth | 顯示記憶體佔用極低、速度快 2～5 倍，適合單機或 Colab |
| LLaMA-Factory | 整合度高、有 WebUI，支援幾乎所有主流 LLM |
| Axolotl | 進階用，用 YAML 設定檔彈性配置 |

**參數建議**：

| 參數 | 建議值 | 說明 |
|------|--------|------|
| LoRA Rank（r） | 8～64 | 對話、風格 8～16；複雜邏輯、領域知識 32～64 |
| LoRA Alpha | 16～128 | 通常為 Rank 的 1～2 倍（如 r=32、α=64） |
| Target Modules | `q_proj, v_proj`（基本）或 `all-linear`（完整） | `all-linear` 學知識效果較好 |
| Learning Rate | 1e-4～3e-4 | 比傳統全量微調高 |
| 量化（QLoRA） | 4-bit（NF4）／8-bit | 7B／13B 模型可壓到 12～16 GB 顯示記憶體內訓練 |
| Max Sequence Length | 2048～4096 | 越長顯示記憶體需求成倍增加 |

## 三、擴散生圖模型的 LoRA

**用途**：角色、畫風、特定物件或姿勢。

**資料集與標註**：

| 項目 | 建議 |
|------|------|
| 角色類圖片 | 15～30 張，包含多角度、表情、服裝變化 |
| 畫風類圖片 | 30～50 張，構圖多變、風格高度一致 |
| 解析度 | SD 1.5 至少 512×512；SDXL／Flux 至少 1024×1024 |
| 標註方式 | 動漫用 Danbooru 標籤（`1girl, blue hair, smiling`）；寫實或 Flux 用完整句子描述光影、主體、背景 |
| 觸發詞 | 每則標註開頭加獨特標籤（如 `char_alex`），生成時用它呼叫 |

**訓練工具**：Kohya_ss（最主流的圖形介面，支援 SD 1.5、SDXL 與部分 Flux）、OneTrainer（介面直觀、參數細、可即時預覽）。

**參數建議**（以 SDXL／Kohya_ss 為例）：

| 參數 | 建議值 | 說明 |
|------|--------|------|
| Network Rank | 16～64 | 一般 32 或 64；越大表達力越強，但檔案大、易過擬合 |
| Network Alpha | 8～32 | Rank 的一半或相同（如 Rank 32、Alpha 16） |
| Optimizer | AdamW8bit／Prodigy | Prodigy 自動調學習率，對新手友善 |
| UNet 學習率 | 5e-5～1e-4 | 圖像特徵的主要學習速度 |
| Text Encoder 學習率 | 1e-5 或 0 | 不需大改模型對文字的理解時可調低或設 0 |
| 總步數 | 1,500～3,000 | 總步數 ＝ 圖片數 × 重複次數 ÷ Batch Size × Epochs |

## 四、輸出與診斷

- **輸出**：LLM 產出含 `adapter_model.safetensors`（或 `.bin`）的資料夾；擴散模型產出單一 `.safetensors` 檔。

| 問題 | LLM 症狀 | 生圖症狀 | 對策 |
|------|----------|----------|------|
| 過擬合 | 只會背訓練集答案，失去通用對話與邏輯 | 雜訊、肢體崩壞、改不了姿勢與背景 | 降低學習率、減少 Epochs、增加資料多樣性 |
| 欠擬合 | 學不會指定風格或格式 | 下觸發詞效果不明顯 | 提高學習率、增加步數或 Rank |

## 我可以怎麼用

- **ERP 知識要不要微調？先問 RAG 夠不夠**：規格書、表結構、作業說明這類「會變動的知識」適合放知識庫用 RAG 查；LoRA 適合固定的**格式與風格**（例如固定格式的需求單分析、公司慣用的 SQL 寫法）。資料會更新的東西訓練進模型，更新一次就得重訓。
- **想試 LLM 微調**：用 Unsloth＋QLoRA 在 Colab 或本機 16 GB 顯卡上跑小模型，資料先整理成 `messages` 格式；先從 Rank 16、少量資料開始，觀察是否過擬合。
- **AI 短片角色 LoRA**：角色準備 15～30 張多角度圖、每張描述開頭加觸發詞；實際做法與時間（16G＋32G 約 33 分鐘）見 [[MiniMax-H3 本機 AI 短片製作原理與踩坑]]。
- **判斷訓練結果的通用原則**：「只會背答案」就是過擬合、「學不會」就是欠擬合，這個判斷也適用評估 Skill 或提示詞是否寫得太死或太鬆。
