# 多專案文件管理與 Git 子模組規範 (Multi-Project Docs & Git Submodule)

在團隊同時管理與開發多個專案時，常面臨「共通開發規範難以同步」與「個別專案文件標籤混淆」的痛點。本規範基於 **Git Submodule（子模組）** 機制，建立了一套兼顧共通規則同步、防呆編輯與防斷鏈的文件管理結構。

---

## 1. 核心痛點分析

1. **複製出錯（編輯混淆）**：若個別專案的詳細說明文件皆使用預設的 `README.md`，當開發者在 VS Code 或其他編輯器中同時開啟 Project A 與 Project B 時，標籤頁將全部顯示為 `README.md`，極易發生複製貼上出錯的慘劇。
2. **規格同步困難**：團隊共通的開發與設計規範（如 API 格式、資料庫欄位規則）若在各專案間重複複製，一旦規範更新，將難以同步至所有專案。

---

## 2. 最終建議之目錄結構 (一入口、一防呆規格、一子模組)

為了實現專案首頁的分流與防呆，建議在各開發專案根目錄實施以下目錄結構：

```text
Project_A/ (專案根目錄)
├── .git/
├── .gitmodules             # Git 子模組設定檔
├── README.md               # 專案首頁 (絕對不能改名，作為導覽分流入口)
├── readme_Project_A.md     # 專案專屬的詳細規格與說明 (帶有名稱的防呆命名)
└── shared-rules/           # 共通規範的 Git 子模組資料夾 (獨立 Repo)
    └── team-docs.md        # 團隊共通開發與設計規範
```

### ✍️ 關鍵檔案內容寫法範例

#### 1. 專案根目錄入口：`README.md`
此檔案是 Git 平台的專案首頁，負責提供一目了然的導覽分流。

```markdown
# 歡迎來到 Project A 首頁

本專案已整合團隊共通規範，請依據您的需求查閱對應文件：

* 📄 [本專案詳細規格與說明](./readme_Project_A.md)
* 🌐 [團隊共通開發與設計規範](./shared-rules/team-docs.md)
```

#### 2. 個別專案說明：`readme_Project_A.md`
存放該專案特有的架構、規格或操作步驟。最上方加上導覽，方便閱讀者快速切換。

```markdown
# Project A 詳細規格與說明

> 🧭 **快速導覽**：[🏠 回專案首頁](./README.md) | [🌐 查看團隊共通規範](./shared-rules/team-docs.md)

---

## 📌 專案簡介
（這裡開始寫專案 A 的特有內容、環境架構、資料庫邏輯等...）
```

#### 3. 共通規範子模組：`shared-rules/team-docs.md`
此檔案存在於獨立的 Git 倉庫中，被所有專案共用。**底部統一連回各專案的 `README.md` 首頁**。

```markdown
# 團隊共通開發與設計規範

這裡記錄了所有專案（Project A、B、C）都必須共同遵守的規則。

## 🛠️ 程式碼與命名規範
- 資料庫欄位一律使用小寫底線 (snake_case)。
- API 回傳格式必須包含 `status`, `data`, `message`。

---

### 🧭 導覽
- [🏠 返回當前專案入口首頁](../README.md)
```

---

## 3. 實務維護注意事項（重要防呆）

### ⚠️ 相對路徑跳脫 (Relative Path Escape)
在共通規範子模組的 `team-docs.md` 中，若要連回引用它的各專案首頁，必須使用 `../README.md`：
- `../` 代表從 `shared-rules/` 資料夾中**跳出來**回到專案根目錄。
- **絕對不可以**在共通規範中寫死 `../readme_Project_A.md`，否則當 Project B 的使用者點擊時，會因為找不到該檔案而發生 404 連結失效錯誤。

### 🧠 人類大腦防呆機制
堅持個別專案說明檔名必須帶有專案名稱（如 `readme_Project_A.md`、`readme_Project_B.md`）：
- **優點**：當開發者同時開啟多個專案時，分頁標籤名稱明確相異，能徹底防範「在錯誤的專案中粘貼或編輯內容」的情形。

---

## 4. Git 子模組日常維護指令

1. **複製新專案時**：當團隊成員 clone 了整合此結構的專案，需執行以下指令以拉取共通規範子模組：
   ```bash
   git submodule update --init --recursive
   ```
2. **同步更新共通規範時**：當共通規範在中央儲存庫更新後，各專案在根目錄執行以下指令即可同步最新文件：
   ```bash
   git submodule update --remote
   ```
