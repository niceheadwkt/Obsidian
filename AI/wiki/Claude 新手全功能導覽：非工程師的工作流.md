# Claude 新手全功能導覽：非工程師的工作流

YouTube 頻道「PAPAYA 電腦教室」（2026-11-26，約 30 分鐘）的【全民 AI 手冊】。影片用動物收容所行政人員「小芳」為主角，她不會寫程式，任務是三個月內提升認養率。影片照工作順序，從帳號設定一路示範到專案、成品、連接器、Skill、排程、Code 模式、部署網站與 Hook，等於一張 Claude 全功能地圖。

**一句話重點**：不會寫程式的行政人員，也能用 Claude 走完整個工作流程

> 素材說明：說明欄的網站連結、練習檔、贊助與會員目錄略過。逐字稿是簡體自動字幕，下文改寫為繁體。各功能的細部操作已有專頁的，這裡只摘流程並連過去。

---

## 一、基本設定與提問

- **Claude 與 Code 兩種模式**：桌面版左上角切換。Claude 跑在官方雲端，電腦關機也不影響；Code 跑在本機，可以直接讀寫電腦裡的檔案，用來開發 App 或做自動化工具。
- **個人偏好與記憶**：設定 →「帳戶」填全名、暱稱、工作性質與回覆原則；「記憶」會在對話中自動記下與你相關的重要資訊。
- **模型與選項**：
  - Haiku 最快，適合小任務；Sonnet 能力與速度最平衡，是日常主力；Opus 適合邏輯複雜、需要深度思考的任務；Fable 更聰明，但消耗額度更多。影片示範選 Sonnet 5.5。
  - 「投入程度」先維持預設的「中」。
  - 權限模式：「手動」每次改檔或執行指令前先確認，「自動」不再逐次詢問。
- **PDF 先轉 Markdown**：PDF 為人類閱讀排版設計，請 Claude 先轉成 `.md` 下載保存，之後重複使用比較省 Token。
- **提問公式五要素**：背景、任務目標、具體要求、驗證方式、輸出格式。
- **省額度四個習慣**（細節見 [[Claude 系統優化與 Token 節省指南]]）：
  1. 需求一次講清楚，不要像 LINE 聊天一樣分好幾則慢慢補：每送出一則，整段對話都要重新處理。
  2. 對話不要拉太長，不同任務開新對話，重要資訊才不會被淹沒。
  3. 對話中不要切換模型：切換會讓快取失效，必須重讀整段上下文。
  4. 留意「五小時」和「每週」兩種額度，用完要等下次重設。

## 三、自動化：子代理、連接器、Skill、排程、瀏覽器

1. **子代理（Subagent）**：Claude 派出的分身助手，同時分頭蒐集不同方向的資料（例：其他收容所提高認養率的做法），最後由 Claude 統整成重點清單。
2. **連接器（MCP）**：點 Gmail 旁的 `+`，Claude 開瀏覽器完成授權；再串 Google 日曆與雲端硬碟。示範把認養詢問信整理成表格、每封信寫好回覆草稿、參觀時間登記到日曆。
3. **Skill**：「任何事只要重複做兩次以上，就適合打包成 Skill」。把回信步驟與注意事項寫成文件，請 Claude 依文件建立回信 Skill；之後可用 `/` 選單叫出，或直接說「到信箱回信給蔡小姐」自動觸發。Skill 本身就是一份可編輯的 Markdown 文件，在「外掛程式 → Skills」管理（詳見 [[Claude Cowork 與 Agent Skill 實務]]）。
4. **排程任務**：Skill 不會自己跑，要搭配排程。可在專案內設定，或直接用白話說「每天早上 9 點到信箱替每封信擬回信草稿」；在左側「排程任務」暫停、刪除或改時間。
5. **瀏覽器自動操作**：Claude 開內建瀏覽器，由使用者自己登入 Google；再把表單題目寫成 Markdown 文件，請 Claude 照著建立 Google 表單，Claude 會像真人一樣讀畫面、逐題填寫。
6. **圖片生成**：Claude 本身不能生圖。可以改用 ChatGPT，或透過 MCP 接 Magnific 等生圖平台；提示詞要寫明模型名稱，Claude 才會呼叫到正確的模型。

## 四、Code 模式：CLAUDE.md、部署、遠端與 Hook

- **網頁設計稿**：在 Claude 指定素材資料夾、套用設計系統，產出含手機版的設計稿，下載成 HTML（包含程式碼與圖片）。
- **切到 Code 模式**：環境選「這台電腦」，專案指到放 HTML 的資料夾。
- **CLAUDE.md**：本機的 Claude Code **不會讀雲端的個人偏好**，要靠 `CLAUDE.md`。輸入 `/init` 掃描專案自動建立；再把雲端設定的個人指示貼給 Claude Code，請它寫到「個人層級（跨專案）」的 `CLAUDE.md`，任何專案都能記得你的身分。
- **部署網站**：註冊 Vercel 免費帳號，在「外掛程式」搜尋並連接 Vercel 連接器，請 Claude 把設計稿轉成可運作的網站並接上 Google 表單連結，部署後得到網址，手機瀏覽也正常。
- **遠端控制（Remote Control）**：在 Claude Code 啟用後，人在外面可以從手機 App 的 Code 分頁找到這個對話繼續下指令；前提是辦公室電腦不能進入睡眠。
- **Hook**：`CLAUDE.md` 只是「柔性提醒」，對話一長仍可能被忘記；Hook 會在特定動作之前或之後「百分之百」自動執行。示範：任何指令想修改認養動物清單就擋下，並顯示「原始資料只能由小芳親自修改」。這和 [[Claude Code 少叮嚀多設限：Opus 5.5 時代最佳實踐]]「規則寫短、安全靠強制機制」的觀點一致。
- **程式碼動畫**：從 Futurepedia 挑動畫風格範本，存成 Markdown；連接 ElevenLabs 連接器配音；把分鏡台詞寫成「動畫腳本」`.md`，請 Claude 用程式碼做 30 秒宣傳動畫（同類做法見 [[claude-motion-explainer 科普解說動畫技能]]）。

## 我可以怎麼用

- **當新人教材的骨架**：要教同仁用 Claude 時，可以借用這部影片「一個角色、一個目標、照工作順序串功能」的編排，把小芳換成 ERP 使用者（例如「月底對帳的會計」），比逐項介紹功能好懂。
- **PDF 規格書先轉 Markdown**：ERP 需求規格、廠商手冊先轉 `.md` 再放進 `AI/raw/` 或專案，入庫與後續問答都比較省 Token。
- **提問五要素對照需求單**：背景、目標、具體要求、驗證方式、輸出格式，正好對應需求單的「現況、需求、規格、驗收、交付物」，可以直接當寫需求或交辦 Claude Code 的範本。
- **Hook 守住不能動的資料**：影片「Hook 擋修改原始清單」的思路，和本機 `zpq` 唯讀限制、Wiki `raw/` 唯讀規則相同。這類絕對不能違反的規則，可以考慮做成 Hook 或 `permissions.deny`，不要只寫在 `CLAUDE.md`。
- **雲端功能只放可公開的資料**：Gmail、雲端硬碟連接器、儀表板分享連結都把資料送到雲端；ERP 正式機資料是公司機密，不要匯出給雲端成品。
- **「做兩次就做成 Skill」**：已經有 `wiki-ingest`、`erp-dajju1` 等 Skill；之後若發現某件事在對話裡交代第二次，就考慮包成 Skill，再搭配排程任務定時跑。
