# Claude 成品製作旅遊行程網站

《數位時代》用 **[[Claude]] 免費版的成品（Artifacts）功能**實測，只輸入中文提示詞，就做出包含航班、住宿、每日景點時間軸、交通段、天氣、行李清單與記帳的手機版旅遊網站，全程不寫程式。文中附一份「福岡六天五夜」完整提示詞，可以直接改目的地沿用。

> 來源：《數位時代》蘇柔瑋整理（2026-11-16，初稿為 AI 編撰），引用 Claude 說明中心（articles/17153992、9547008 分享成品）。剪輯檔的 `source` 欄位網址是 `article/93045/royalcanin_202611`，和內容不符，可能是剪輯時抓錯網址；內容確定是這篇旅遊網站教學。

## 一、免費版與 Pro 的差異

依文章實測（免費版）與說明中心整理（Pro），**建立、修改、保留成品免費版都可以**，差在分享、官方資料儲存和額度：

| 項目 | 免費版 | Pro |
| :--- | :--- | :--- |
| 費用 | 免費 | 美國官網 20 美元／月；台灣 App Store 新台幣 690 元／月 |
| 建立、對話修改、保存成品 | 支援 | 支援 |
| 打勾、記帳紀錄 | 依網站設計存在瀏覽器本機（換裝置、換瀏覽器、清除資料可能遺失） | 可用官方成品資料儲存功能（網頁版與桌面版），個人或共享儲存 |
| 用連結分享成品 | **不支援** | 支援（分享設定只能在網頁版或桌面版改，手機 App 不行） |
| 使用量 | 有上限，反覆修改容易用完 | 每個工作階段額度較高 |

- 依官方說明，用連結分享給旅伴時，對方**只能查看已儲存的紀錄，不能共同修改**，所以無法多人同步打勾或記帳。
- 2026-09-16 前建立的舊版成品另有發布規則，新做的成品不適用。
- 免費版的替代分享方式：請 Claude 提供**單一 HTML 檔**，用 LINE 等傳給旅伴。HTML 只包含網站本身，不含你的打勾與記帳紀錄，雙方資料也不會同步。若程式碼、圖片都包在檔案內，沒網路也能看行程（Google Maps、即時天氣仍需網路）。

> [!NOTE]
> 方案價格與功能以 2026-11 文章當時為準。收費方案的詳細比較另見 [[Claude 系統優化與 Token 節省指南]]（額度控制）。

## 二、提示詞 6 個設定欄位

開始前先確認：設定 →「功能」→ 開啟「程式碼執行和檔案建立」（新版叫「建立和編輯檔案」）。

| 欄位 | 要提供的內容 | 範例 |
| :--- | :--- | :--- |
| 旅程資訊 | 目的地、日期、天數、住宿晚數 | 福岡 6 天 5 夜，2026/11/13～11/18 |
| 視覺風格 | 配色、字型、圓角、插圖 | 博多藍 #23406B，圓角 16px |
| 導覽方式 | 分頁數、按鈕位置、切換方式 | 標題下方四顆大按鈕 |
| 分頁功能 | 每個分頁有哪些資訊 | 首頁放航班、倒數與插圖 |
| 資訊細節 | 行程卡片、交通與店家資訊 | 餐廳標示菜色、預算、訂位建議 |
| 動畫與其他 | 動態效果、儲存方式、無障礙 | 輕微動畫，支援減少動態效果 |

只說「幫我做一個日本旅遊網站」也做得出來，但版面與功能容易和期待不同。

## 三、4 步驟製作流程

1. **輸入提示詞，最後加一句「先出規格」**：「請先閱讀並整理以上需求，提出完整的網站製作規格供我確認。」先檢查文字版規格，比直接生成網站再重做省額度。
2. **檢查 Claude 整理的規格**：實測中 Claude 主動指出 3 個問題——日期換算後住宿晚數不一致、指定字型不一定能載入、天氣無法自動即時更新。逐項回覆後再說「可以開始製作」。
3. **先用範例資料測試**：還沒訂機票住宿時，請 Claude「按照合理動線產生範例資料，並清楚標示『範例』」，先測版面、日期切換、交通段、記帳與清單。範例資料可能是虛構的。
4. **一次改一件事，再換成真實資料**：例如「首頁最上方插圖動畫拿掉，其他保持不變」「交通資訊獨立一列」「日期按鈕放大」「住宿卡片加 Google 地圖連結」。設計定案後再提供真實航班、飯店、餐廳。最後**用手機實際開啟**檢查按鈕、地圖連結、記帳、清單。

## 四、福岡範例提示詞的結構

完整提示詞見原文（可直接複製）。結構分九段，改目的地時主要調整第一段、配色、插圖題材與購物區域：

1. **基本資訊**：目的地、日期；航班住宿行程先放標示「範例」的示範內容。
2. **視覺設計**：日系旅遊手帳風；六色在地配色（博多藍、明太子紅、燈籠黃、梅花粉、松葉綠、淺水藍）；白卡片、1.5px 深藍邊框、16px 圓角；不用漸層；Noto Sans TC、內文至少 16px；首頁用 SVG 畫福岡塔、中洲屋台、那珂川、太宰府梅花。
3. **導覽**：總覽／每日行程／行前清單／住宿速查四區；按鈕高度至少 64px；選取中深藍底；選單不固定；每區底部有返回主選單。
4. **總覽**：插畫、出發倒數（出發後改顯示第幾天與下一個行程）；登機證風格航班卡，**要考慮台日時差**。
5. **每日行程**：日期按鈕；捲動時保持可見的天氣與住宿摘要；時間軸卡片依類型分色（景點淺藍、美食暖黃、購物柔粉、機場飯店中性色）；**相鄰卡片之間放交通指引**（工具、方向、起訖站、時間、步行分鐘）；景點可打勾、地圖按鈕、晴雨備案切換、每日日圓記帳並依自訂匯率換新台幣。
6. **行前清單**：行前待辦與行李兩類，可勾選、增刪，顯示進度。
7. **住宿與實用資訊**：地址、車站、步行時間、入退房、訂房編號、地圖按鈕；分區伴手禮與退稅提醒；訂位編號、保險、日本緊急電話（警察 110、消防救護 119）；六天總支出。
8. **動態效果**：燈籠輕晃、蒸氣、河面波紋；切換日期時卡片依序彈出；支援裝置的減少動態效果設定。
9. **製作方式**：手機優先、示範資料要標示、盡量整合成單一 HTML、方便日後更新。

結尾同樣要求「先列規格與問題，確認後再製作」。

## 五、使用限制

| 限制 | 建議 |
| :--- | :--- |
| 天氣無法即時更新 | 製作時請 Claude 填入天氣資訊，旅途中自行確認 |
| 字型可能載入不了 | 用替代字型，並在手機上確認顯示 |
| 航班、住宿可能是虛構 | 出發前換成實際訂位資料，核對時間與地址 |
| 交通與營業資訊可能不準 | 用 Google Maps、交通業者、店家官網再確認 |

## 六、重點整理

- **先規格、後生成**：要求 Claude 先回覆規格與疑問，是省額度、少重做最有效的一句話。這和 [[AI 圍棋陪練：專案指示與成品小遊戲]] 要求「答案先給家長核對」、[[Claude 高階提示詞與應用場景]] 的「改稿」心法是同一套：AI 先產出，人負責確認。
- **範例資料要標示**：還沒有真實資料時用標示「範例」的假資料先測功能，避免把虛構內容當真。
- **資料保存要先想清楚**：免費版的打勾與記帳只在本機瀏覽器；要跨裝置或分享，就需要付費方案的官方儲存，而且分享出去的人仍然不能共同修改。
