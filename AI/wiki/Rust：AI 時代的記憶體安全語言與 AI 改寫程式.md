# Rust：AI 時代的記憶體安全語言與 AI 改寫程式

整理自 YouTube 頻道 P & H 的影片〈AI 時代，只能靠 Rust 了？〉（2026-10-20，含逐字稿與參考資料清單）。影片從記憶體安全講起，說明 Rust 是什麼、在 AI 技術堆疊中的位置，以及為什麼 AI 公司紛紛用 AI 把程式改寫成 Rust。

**一句話重點**：AI 改寫程式時代，編譯器嚴格的 Rust 最好驗證

## 一、Rust 是什麼：第三條路的記憶體管理

- **編譯式語言**，速度與 C++ 同等級，最大賣點是**記憶體安全**。
- 三種記憶體管理方式：
  - **C／C++**：自己管理，過早釋放或忘了釋放都會出錯。
  - **Python／Go**：自動回收（GC），安全但回收時程式會停頓。
  - **Rust**：沒有 GC。每塊記憶體只有一個**主人（ownership）**，主人不用就自動釋放；別人要用只能**借用（borrow）**，編譯器檢查每一次借用。
- 例：指標指向 vector 第一個元素後再 push，vector 搬家、舊記憶體釋放。C++ 編譯照過、執行印出亂碼；Rust 因「還在借用中不准改」**直接編譯失敗**——錯誤停在開發者電腦上，不會跑到使用者那邊。
- 規模：Microsoft 每年修補的安全漏洞約**七成**是記憶體安全問題，Chrome 嚴重漏洞也約七成；2024 年美國白宮 ONCD 報告建議改用記憶體安全語言，舉例即 Rust。

## 二、Rust 在 AI 技術堆疊中的位置

影片以 GitHub 專案頁的 Languages 欄位實查：

| 層次 | 主要語言 | 例子 |
|---|---|---|
| 寫模型、做實驗 | Python | PyTorch 約三分之二 Python，其餘多為 C++／CUDA，**無 Rust** |
| GPU 大量運算 | C++、CUDA | — |
| 中間層：又要快又不能出錯 | **Rust** | Codex CLI 約 97%、tiktoken 切字核心約 35%、safetensors 過半、uv 98%、Ruff 97%、Polars 約六成、向量資料庫近九成 |

## 三、四種語言比一比

| | 速度 | 記憶體安全 | 多執行緒 |
|---|---|---|---|
| Python | 最慢 | GC，安全但會停頓 | 寫得出來 |
| Go | 快 | GC，安全但會停頓 | 很好寫 |
| C++ | 最快 | 不停頓，靠人小心 | 寫得出來但易錯 |
| Rust | 最快 | 不停頓，編譯器擋錯 | 不寫 `unsafe` 就保證無**資料競速** |

代價：學習曲線陡，編譯器嚴格，新手常卡關。

## 四、改用 Rust 的實際成效

- **Android**（Google，2025-11）：新程式改用 Rust 後，記憶體安全漏洞**首次降到所有漏洞的兩成以下**；Rust 程式碼記憶體漏洞密度比 C／C++ 低約**一千倍**。開發沒變慢：中大型修改被撤回比例低約四倍，審查時間少約四分之一。
- **Linux 核心**：2022 年以「實驗」名義讓 Rust 進核心，2025-12 維護者高峰會結論為**實驗成功、Rust 會留下來**；Android binder 驅動已用 Rust 寫進核心，NVIDIA 新驅動 Nova 也用 Rust。

## 五、AI 改寫程式的時代

以前不全面改寫是因為程式太多、人工改不完；現在改寫可以交給 AI，連 AI 寫程式的工具本身都換成 Rust：

- **Codex CLI**：2025 年從 TypeScript 改寫成 Rust。
- **GitHub Copilot runtime**：從 TypeScript 改成 Rust，**83 萬行**，主要由一位工程師指揮 AI agent，約 **14.5 週**完成。
- **Bun**（Claude Code 底層執行環境）：作者用一群平行的 Claude agent，**11 天**從 Zig 改寫成 Rust；影片稱 2026 年 6 月之後的 Claude Code 跑的就是 Rust 版。
- **Google giflib**：安全團隊用 Gemini 把 C 函式庫改寫成 Rust，**不直接上線**——先用 3,000 萬張真實 GIF 比對輸出與原版完全相同，再跑 6 天、2 億次差異測試。上線後不久原 C 版爆出新的記憶體漏洞，Google 服務早已換成 Rust 版而不受影響。
- **Google Gemini 4 Argon**（2026-09-30 官方部落格）：agent 正把 Google 的 C／C++ 程式碼搬到 Rust，從幾萬行函式庫到八十萬行作業系統核心。

## 六、為什麼偏偏是 Rust：可快速驗證

- AI 寫的程式也會出錯，所以 **AI 時代選語言，要看寫出來的程式能不能被快速驗證**。
- Rust 強型別、規則嚴格，編譯器先檢查三件事：**記憶體安全、型別、資料競速**。這些錯 AI 自己編譯一次就知道，不用等人抓。
- 對 AI 而言，**編譯器像一個不會累的審稿員**：寫錯就退回，改到編譯通過為止。

## 七、趣聞：名稱與吉祥物

- 官方標誌是中間有 R 的**齒輪**；紅色螃蟹 **Ferris** 是社群非官方吉祥物（CC0）。
- 2006 年創辦人 Graydon Hoare 因大樓電梯軟體當機、爬 21 樓回家而開始設計新語言，名稱取自生命力超強的**鏽菌**。Ferris 是鐵鏽色、諧音 ferrous（含鐵）；使用者自稱 Rustacean（crustacean 去掉 c）。
- 2025 年 Stack Overflow 開發者調查，最受推崇語言仍是 Rust（72%）。

## 我可以怎麼用

- **「AI 寫完能自動驗證」作為工具選擇原則**：ERP 是 Java（同為強型別編譯語言），讓 AI 改 ERP 程式後，先編譯一次再交付，把編譯器當第一道審稿員；個人 Python 腳本則可補型別提示＋檢查（Ruff、mypy）彌補動態語言缺少的這一關。呼應 [[AI 開發的 CI-CD 品管防線與兩層驗證]]。
- **用 AI 搬移舊程式時學 giflib 的驗證法**：改寫或重構舊批次、報表程式時，不要只看「程式能跑」，而是拿大量正式資料比對新舊版輸出完全一致（如同 RQ 案以 SQL 預期值逐筆比對），再上線。
- **認識日常工具的底層**：uv、Ruff、Codex CLI、Claude Code（Bun）都是 Rust 寫的，速度快與少當機的原因在此；遇到這些工具問題時知道它們是原生執行檔而非 Node／Python 套件。
