![](https://www.youtube.com/watch?v=1nomxygMILI)

很多人把 AI 裝在自己的電腦上，接上 agent 叫它做事，結果它一直失敗，就以為本地模型太笨。其實很多時候是設定錯了：Ollama 在顯示記憶體小於 24GB 的機器上，預設 context 只有 4k，但 OpenClaw 這類 agent 需要 64k 以上。  
  
這一集照記憶體大小，從 16GB 一路講到 128GB：每一級能跑哪一顆模型、多快、適合做什麼。再講為什麼有的大模型反而比較快（MoE）、要用 LM Studio、Ollama 還是 llama.cpp、哪些用法真的有人做成功、哪些會讓你失望，最後是新手最常踩的五個坑，跟一張一個下午就能鎖好的安全清單。  
  
片中所有速度（tok/s）都是社群上分享的實測，不是我們自己量的；同一台機器換軟體、換設定就會差很多，看大概就好。  
  
📌 七句照做  
1\. 要接 agent，先把 context 拉到 64k 以上  
2\. 4-bit 模型 ≈ 參數量 × 0.6 GB，再多留空間給 context  
3\. 用 Mac 的話，先照記憶體的四分之三來算  
4\. 16GB 跑小模型；32GB 跑 27B 等級；64GB 開長 context；128GB 才換到大模型  
5\. 想要快，先試 MoE 模型，再試著換一個軟體  
6\. 難的交給雲端，私密的、重複的留在本地  
7\. Ollama 保持只聽本機，agent 的資料夾裡不要放密碼

### 三、為什麼有的大模型反而快（MoE）

**6:52** · 第三段。

**6:53** · 剛剛有個奇怪的地方：32 GB 那台， 26B 的 Gemma 反而比 27B 的 Qwen 快好幾倍； 128 GB 那台，1,250 億參數的模型，跑得比 27B 還快。

**7:03** · 原因是一種叫 MoE 的設計。

**7:06** · 先講為什麼模型會慢。

**7:07** · AI 每寫一個 token， 都要把模型的參數從記憶體裡讀一遍。

**7:11** · 記憶體一秒鐘能搬多少資料，叫做頻寬。

**7:13** · 所以模型越大，每寫一個字要搬的東西越多，就越慢。

**7:17** · 一般的模型叫稠密模型，寫每一個字， 全部的參數都要動到。

**7:21** · MoE 的意思是「專家混合」，模型裡面分成很多小組專家， 每寫一個字，只叫其中幾個專家出來。

**7:28** · 像 Qwen3.6 35B，名字後面的 A3B， 意思就是每次只動用大約 30 億個參數。

**7:34** · 要搬的東西少，速度就快很多。

**7:36** · 社群上有一個實測，同一台 M4 Pro 的電腦， 稠密的 27B 每秒 14.7 個 token， MoE 的 35B 每秒 78.8 個，大了一點的模型， 反而快了五倍。

**7:46** · 但這裡有一個常見的誤解，網路上也有人講錯： MoE 只是速度快，記憶體不會比較省。

**7:52** · 所有的專家都要放在記憶體裡待命，所以 35B 的 MoE， 還是要 22 GB 左右的空間。

**7:57** · 記住這句話：放不放得下看全部， 速度看每次叫出來的那幾個。

**8:02** · MoE 也不是完全沒有缺點。

**8:04** · 社群上有不少人回報，同樣大小的情況下， 稠密模型做長的 agent 任務比較穩，MoE 有時候會失手。

**8:10** · 快跟穩，看你的工作需要哪一個。

### 四、用什麼軟體：LM Studio、Ollama、llama.cpp

**8:13** · 第四段，軟體。

**8:15** · 模型是一個檔案，你還需要一個軟體把它跑起來。

**8:18** · 新手最常碰到的有三個。

**8:19** · 第一個是 LM Studio，有完整的介面， 像一個模型的 App Store，搜尋、下載、聊天都在裡面， 而且會告訴你哪一顆放得下。

**8:27** · Mac 上要選 MLX 格式，這是 Apple 自己做的格式， 在 Mac 上通常比較快。

**8:33** · 第二個是 Ollama，它主要是在背景跑， 讓其他的 App 來接，像 OpenClaw、 Claude Code 這類 agent 工具，接 Ollama 最方便。

**8:40** · 第三個是 llama.cpp， 它是很多軟體底下真正在跑模型的引擎， Ollama 跟 LM Studio 都用過它。

**8:47** · 功能最多，但要自己打指令，適合想動手調整的人。

**8:51** · 為什麼軟體很重要？

**8:52** · 社群上有人用同一台 32 GB 的 M6 Mac mini、 同一顆 Qwen 27B，只換跑模型的軟體跟檔案格式， 速度就從每秒大約八個，變成 21 個左右，差了快三倍。

**9:03** · 他說他沒有換任何硬體，只換了軟體。

**9:05** · 所以覺得慢的時候，先不要急著換電腦。

**9:08** · 先換一個軟體試試看、把軟體更新到最新版， 在 Mac 上確認用的是 MLX 格式，很多時候速度就差很多。

### 五、拿來做什麼、做不好什麼

**9:15** · 第五段。

**9:15** · 模型裝好了，到底能拿來做什麼？

**9:18** · 這一段只講社群上有人實際做成功、有交代過程的例子。

**9:22** · 第一個，私人文件問答。

**9:24** · 合約、病歷、財務資料、客戶的檔案， 這些東西很多人不敢丟到雲端。

**9:28** · 放在本地，你可以把整疊文件丟給模型問問題， 網路關掉也能用。

**9:32** · 這也是本地 AI 最常被提到的理由。

**9:35** · 第二個，一整批的重複工作，丟著讓它跑一個晚上。

**9:39** · 社群上有一個人拿 40 張範例發票， 讓本地模型一張一張讀出來、整理成試算表， 40 張全部正確。

**9:45** · 這種事不需要最聰明的模型， 需要的是有人願意不嫌煩地做完。

**9:49** · 第三個，整理自己的帳。

**9:51** · 有人用 32 GB 的 M6 Mac mini，加上 Gemma 4 26B， 叫本地的 coding agent 寫一個小程式， 把銀行交易紀錄自動分類、算出每一類花多少錢， 最後還做了一個圖表儀表板。

**10:02** · 銀行資料完全沒有離開那台電腦。

**10:04** · 第四個，整理影片庫。

**10:06** · 有人用一台 M4 Mac mini 跑一顆大約 6 GB 的看圖模型， 讓它整夜幫幾千支影片片段寫說明，跑了 16 個小時以上， 他的素材庫從此可以用文字搜尋。

**10:16** · 整個過程，那台 Mac mini 的風扇幾乎沒有聲音。

**10:19** · 第五個，也是最實用的觀念：雲端的大模型負責規劃， 本地的小模型負責做事。

**10:24** · 雲端模型比較聰明，讓它想清楚要做什麼、分成哪幾步； 本地模型負責大量讀資料、做重複的小工作。

**10:31** · 大公司也在往這個方向走。

**10:32** · Microsoft 10 月宣布， GitHub Copilot 會依照任務的難度， 把工作分給雲端或電腦裡的本地模型； Perplexity 九月在 Mac 上推出的功能， 則是讓雲端負責規劃跟搜尋， 私密的檔案交給 Mac 上的本地模型處理。

**10:45** · 所以重點是兩邊一起用：難的交給雲端，私密的、量大的、 重複的，留在自己的電腦。

**10:51** · 講完能做的，也要講做不好的。

**10:53** · 先知道哪裡會失望，就不會花一個週末之後覺得被騙。

**10:57** · 第一，在大專案裡當 coding agent。

**10:59** · 社群上有人用 M5 Pro 的筆電跑 Qwen 27B， 叫它看一整個專案、找出 bug，跑了 3 分鐘以上， 風扇全速、context 幾乎塞滿，一段程式碼都沒有寫出來。

**11:09** · 原因是一個很多人沒注意到的數字：讀 prompt 的速度。

**11:13** · 模型開始寫之前，要先把你給它的東西全部讀完。

**11:15** · 一整個專案動不動就是幾萬個 token， Mac 讀長 prompt 特別慢，於是你看到的就是它一直在想， 什麼都沒寫。

**11:23** · 第二，拿 9B 這種小模型當 agent。

**11:25** · 有人用 9B 的模型叫 agent 幫他做一個家用伺服器的儀表板， 做出來的畫面，把明明正常的服務都標成離線， 網頁上的按鈕也沒有作用。

**11:33** · 換成雲端的模型，一次就做好了。

**11:36** · 第三，壓到四位元以下。

**11:37** · 為了塞進比較小的電腦，有些版本壓到三位元、二位元。

**11:41** · 社群裡很多人的經驗是，壓得太小， 最先壞掉的是工具呼叫， 也就是 agent 叫其他程式做事的那個格式。

**11:48** · 只是聊天可能還好，要做 agent 就盡量留在四位元以上。

### 六、新手五個坑＋一個下午鎖好的清單

**11:52** · 第六段，新手最常踩的五個坑。

**11:54** · 大部分人覺得本地 AI 很笨、很慢，都是踩到這幾個。

**11:58** · 第一個坑，就是開場講的 context 太短。

**12:00** · Ollama 在顯示記憶體小於 24 GB 的機器上， 預設只有 4,000 個 token。

**12:05** · 要接 agent，記得到設定裡把 context 的滑桿拉高， OpenClaw 建議至少 64,000。

**12:10** · 拉高會吃更多記憶體，所以這也是為什麼要多留空間。

**12:13** · 第二個坑，chat template 掉了。

**12:15** · 每一顆模型都有自己習慣的對話格式， 叫做 chat template，就像它聽得懂的說話方式。

**12:21** · 有些網路上重新打包的版本沒有把這份格式帶進來， 軟體就會默默換成通用的格式，模型會明顯變笨。

**12:27** · 解法是下載官方，或是很多人用、評價好的打包版本， 有問題先換一個版本試試。

**12:33** · 第三個坑，KV cache 被壓縮。

**12:35** · KV cache 是模型用來記住前面對話的筆記， context 開越長，這份筆記越大， 所以很多教學會教你把它壓小來省空間。

**12:44** · 可是有一個硬體評測團隊挑了六個比較難的工具呼叫， 把這份筆記壓成八位元，六個裡面有五個格式壞掉。

**12:52** · 他們也說，這六個是特別挑過的難題， 不代表平常每六次就會壞 5 次。

**12:57** · 只是聊天，壓一點影響不大；要做 agent， 這個設定先不要動。

**13:02** · 第四個坑，只看「放得下」，沒看能不能用。

**13:06** · 模型放得進去，不代表跑得順。

**13:08** · 有人用 16 GB 的顯示卡硬塞一個壓得比較少的 27B， 記憶體用到 96%，整台電腦當機，重開了兩次。

**13:16** · 放得下之後，還要留空間給 context， 也要看讀 prompt 跟寫字的速度你等不等得下去。

**13:22** · 第五個坑，以為本地就一定安全。

**13:25** · 資料不出門確實比較私密， 可是資安公司 SentinelOne 跟 Censys 今年發現， 網路上有 175,108 台 Ollama 伺服器直接對外開放、 沒有密碼，任何人都可以拿來用， 將近一半還開了工具呼叫的功能。

**13:39** · Ollama 預設只聽你自己這台電腦， 這些伺服器多半是被改成對所有網路開放。

**13:44** · 另外，模型檔本身不會執行程式， 可是你給了 agent 工具權限，它就能動你的檔案。

**13:50** · 所以重點不是模型在哪裡跑，而是它碰得到什麼。

**13:54** · 這裡給你一張一個下午就能做完的清單。

**13:57** · 第一，Ollama 保持只聽本機， 不要為了方便改成對所有網路開放，要從外面連回家， 用 Tailscale 這類私人網路。

**14:05** · 第二，把 Ollama、LM Studio 更新到最新版， Ollama 這類軟體都修過好幾次安全漏洞。

**14:11** · 第三，要給工具權限的模型，只用官方或知名來源的檔案。

**14:16** · 第四，agent 工作的資料夾裡，不要放密碼、 金鑰這些東西。

**14:20** · 第五，LM Studio 開本地伺服器的話， 打開需要驗證的選項。

### 什麼時候才該升級＋七句整理

**14:25** · 最後，什麼時候才該升級？

**14:27** · 如果你在 16 GB，每天都想跑 agent、 想用 27B 等級的模型，那 32 GB 是有感的升級。

**14:33** · 如果你在 32 GB，常常要讀很長的文件、 讓 agent 跑很久，64 GB 才有意義。

**14:39** · 想跑 100B 以上的大模型，就要到 128 GB。

**14:43** · 除了這幾種情況，先把軟體換對、設定調好， 你手上這台多半還有很多沒用到的力氣。

**14:48** · 至於要不要買新電腦、算起來划不划算，現在記憶體漲價， 大記憶體的機器特別貴，我們另一集算給你看。

**14:56** · 我們把這一集整理成七句可以直接照做的話。

**14:59** · 第一，要接 agent，先把 context 拉到 64,000 以上。

**15:04** · 第二，一顆四位元的模型，大約需要參數量乘以 0.6 GB， 再多留空間給 context。

**15:10** · 第三，用 Mac 的話，先照記憶體的四分之三來算。

**15:13** · 第四，16 GB 跑小模型；32 GB 跑 27B 等級的好用模型； 64 GB 是開長 context；128 GB 才換到大模型。

**15:23** · 第五，想要快，先試 MoE 的模型，再試著換一個軟體。

**15:27** · 第六，難的交給雲端，私密的、重複的留在本地。

**15:32** · 第七，Ollama 保持只聽本機， agent 的資料夾裡不要放密碼。
