## 坑一：按下 F8 完全無法接收麥克風內容（麥克風無法啟動）

### 1. 問題表象
軟體安裝並登入後，按下預設的錄音熱鍵 `F8`，麥克風毫無反應，無法啟動錄音，亦無法轉錄文字。

### 2. 底層深度逆向排查
1. **程式架構分析**：
   * 透過反編譯 `SogaType.dll` 核心組件，發現其採用 .NET 8 WPF/WinForms 架構，底層音訊擷取模組依賴 **NAudio 的 WinMM `WaveInEvent`**（Windows MultiMedia Extensions 舊式音訊驅動介面）。
2. **WinMM 驅動裝置檢測**：
   * 執行 Win32 原生 API 測試 `waveInGetNumDevs()`，回傳值竟為 **`0`**（系統中不存在任何可用的 WinMM 音訊擷取裝置）。
3. **CoreAudio 底層狀態查詢**：
   * 透過 Windows CoreAudio COM 介面（`IMMDeviceEnumerator`）檢測系統端點：
     * 呼叫 `GetDefaultAudioEndpoint(eCapture, ...)` 回傳錯誤代碼 `0x80070490`（找不到項目 / 查無預設錄音裝置）。
     * 列舉所有錄音端點發現，內建「麥克風陣列（Realtek(R) Audio）」的裝置狀態為 `0x2`（**`DEVICE_STATE_DISABLED`**，被系統底層停用）。
4. **根本原因**：
   * 雖然麥克風隱私權限開啟，但該硬體端點在 Windows 音訊子系統中處於停用狀態。依賴 WinMM `waveInOpen` 的 SogaType 啟動錄音時拋出 `NAudio.MmException: BadDeviceId`，導致錄音完全無法啟動。

### 3. 解決方案
* **強制啟用端點並設為預設**：
  編寫腳本呼叫 Windows 音訊核心未公開介面 `IPolicyConfig`：
  ```csharp
  client.SetEndpointVisibility(micDeviceId, true); // 設為可見與啟用 (State: 0x1 Active)
  client.SetDefaultEndpoint(micDeviceId, 0);       // eConsole
  client.SetDefaultEndpoint(micDeviceId, 1);       // eMultimedia
  client.SetDefaultEndpoint(micDeviceId, 2);       // eCommunications
  ```
* **驗證結果**：
  * `waveInGetNumDevs()` 成功恢復為 `1`（抓到 `Microphone Array (Realtek(R) Audio)`）。
  * 執行 1 秒 PCM 音訊擷取測試，順利收音 32,000 位元組。
  * 重啟 SogaType 背景程序，完成音訊裝置重新掛載。

### 4. 深度技術剖析：為什麼麥克風端點會變成 0x2 (DEVICE_STATE_DISABLED)？

在 Windows CoreAudio（WASAPI）系統架構中，音訊端點定義了四種狀態常數：
* `0x1`（`DEVICE_STATE_ACTIVE`）：正常啟用
* `0x2`（**`DEVICE_STATE_DISABLED`**）：**端點被系統或軟體停用**
* `0x4`（`DEVICE_STATE_NOTPRESENT`）：硬體不存在
* `0x8`（`DEVICE_STATE_UNPLUGGED`）：未插上接頭

實體內建的「麥克風陣列（Realtek(R) Audio）」會轉變成 `0x2`，代表**硬體驅動正常且已被系統辨識，但邏輯音訊端點被軟體策略或系統指令關閉**。在 Windows 11 與 ASUS ROG Zephyrus G14 筆電架構下，常見肇因包含以下五大面向：

1. **Windows 11 設定中的「不允許」開關（最常見誤觸）**：
   * 前往「設定」➔「系統」➔「音效」➔「麥克風陣列」內容頁，頂部有「允許應用程式和 Windows 將此裝置用於音訊」設定。
   * 一旦誤點【不允許】，Windows 不會在裝置管理員停用硬體驅動，而是直接在 CoreAudio 原則資料庫中將該端點標記為 `0x2`，導致所有錄音軟體查無預設裝置（回傳 `0x80070490`）。
2. **ASUS ROG Zephyrus 專屬機制（Armoury Crate / AI 降噪端點切換）**：
   * **實體靜音鍵連動副作用**：ROG G14 具備獨立麥克風靜音鍵（M4 / Fn + F4），部分版本 ASUS Hotkey 服務在觸發靜音時會直接切換端點狀態；若系統休眠喚醒或異常重啟，端點可能卡死在停用。
   * **雙向 AI 降噪（Two-Way AI Noise Cancelation）**：啟用時 ASUS 會建立虛擬麥克風端點，並可能將原生 Realtek 陣列停用以防收音重疊；當虛擬端點異常或軟體更新時，原生端點未被正確還原。
3. **Windows Update 或 Realtek 驅動程式背景更新（端點遷移衝突）**：
   * Windows Update 自動推送 Realtek High Definition Audio 或 Realtek APO 更新時，會重新執行端點遷移（Endpoint Migration）。若系統判定「3.5 mm 複合式插孔」優先，內建麥克風陣列有時會被預設初始化為 `Disabled`。
4. **曾安裝第三方虛擬音訊或語音輸入工具（卸載或退出遺留）**：
   * 先前若曾安裝/執行過 Typeless、NoType、VoiceType、Voicemeeter 或視訊會議軟體，這類軟體在嘗試獨占音訊通道時若異常崩潰或卸載不完整，常遺留被關閉的原生端點。
5. **現代待機（Modern Standby / S0ix）休眠喚醒異常**：
   * ROG 筆電喚醒時，若 Realtek 音訊晶片自 D3 節能狀態上電的時間略慢於 Windows 音訊服務（`Audiosrv`）的輪詢，系統可能誤判「裝置未就緒」而標記為暫時停用。

#### 快速自我檢查與修復技巧
若未來再次發生，最簡便的圖形化檢查方式：
1. 按 `Win + R` 輸入 **`mmsys.cpl`** 開啟傳統 Windows 聲音控制台。
2. 切換至**「錄音」**分頁，在空白處右鍵勾選**「顯示已停用的裝置」**與**「顯示已中斷連線的裝置」**。
3. 若「麥克風陣列」呈現灰色停用狀態，直接右鍵點選**「啟用」**即可快速恢復。

## 坑二：ASUS ROG 筆電實體鍵盤 F8 鍵無作用

### 1. 問題表象
在修復麥克風端點後，單獨按鍵盤上的 `F8` 鍵依然無反應。

### 2. 根本原因
* 本機為 **ASUS ROG Zephyrus G14** 筆電，鍵盤頂排 F1～F12 預設受 ASUS Armoury Crate / ASUS Hotkey 控制為**多媒體快捷鍵**。
* 實體 `F8` 鍵預設功能為「調高螢幕亮度（Brightness Up）」，並不會送出標準虛擬鍵碼 `VK_F8`（119），因此 SogaType 透過 Win32 `RegisterHotKey` 註冊的 `F8` 永遠收不到訊號。

### 3. 解決方案
1. **硬體組合鍵**：改按 **`Fn + F8`** 即可正確送出 `F8` 鍵碼。
2. **切換 Fn Lock**：透過筆電鍵盤切換 Fn Lock，或在 G-Helper / Armoury Crate 設定中將 F 功能鍵改為預設標準功能鍵。
3. **軟體重設熱鍵**：直接在 SogaType 的「設定…」面板中，將錄音熱鍵更換為其他不需搭配 Fn 的按鍵組合。

## 坑三：改用 `Ctrl + Space` 後，出現【辨識中...】後無動作且沒顯示文字

### 1. 問題表象
將錄音熱鍵改為 `Ctrl + Space`。按一下出現【聆聽中...】，再按一下出現【辨識中...】，隨後視窗提示消失，但畫面上完全沒有打出任何文字。

### 2. 深度除錯與真相發現
1. **剪貼簿檢驗**：
   * 檢查 Windows 系統剪貼簿內容，發現文字竟然**早已成功辨識並存於剪貼簿中**：
     > `有吃線辨識中`
     > （口述內容為「有出現辨識中」，麥克風收音、雲端傳輸與 AI 校正全程成功）
2. **SogaType 文字注入機制**：
   * 逆向解析 `SogaType.dll` 的 `Paste` 與 `SendCtrlV` 方法，其輸出文字的實作方式為：
     1. 將 AI 辨識完成之字串寫入 Windows 系統剪貼簿（`SetClipboardUnicode`）。
     2. 呼叫 Win32 API `keybd_event` 模擬發送鍵盤訊號：`Ctrl 按下` ➔ `V 按下` ➔ `V 放開` ➔ `Ctrl 放開`。
3. **失效原因剖析**：
   * **原因 A：游標未在輸入焦點內**：如果觸發熱鍵時，滑鼠未先在文字編輯區（如記事本、輸入框）點出閃爍游標 `|`，模擬的 `Ctrl + V` 會因無目標而貼空。
   * **原因 B：`Ctrl + Space` 系統熱鍵衝突**：
     * 在 Windows 系統中，`Ctrl + Space` 預設是「輸入法中英文切換 / 輸入法開關」。
     * 連續按兩次 `Ctrl + Space`（開始與結束）會引發輸入法切換與選字視窗狀態跳動，導致目前輸入框焦點被輸入法核心重置或攔截，隨後發送的 `Ctrl + V` 遭到吞噬。

## 坑四：Notepad++ 可正常自動貼上，但終端機 / 對談視窗卻完全失效（終極核心坑）

### 1. 問題表象
同樣使用 SogaType 語音輸入，在 Notepad++ 中可以秒速自動打出文字；但在目前的 AI 對話視窗（Windows Terminal）中，卻依然卡在【辨識中...】結束後毫無動作。

### 2. 深入權限隔離排查（UIPI 鐵證）
透過 Python 檢測執行中的程式 Token 提權（Elevation）層級：

| 程序名稱 | 處理程序 PID | 提權狀態（Elevated） | SogaType 能否自動貼上 |
| :--- | :--- | :--- | :--- |
| **SogaType.exe** | 33956 | **False（一般使用者權限）** | ─（發送端） |
| **notepad++.exe** | 16140 | **False（一般使用者權限）** | **成功貼上** |
| **WindowsTerminal.exe (wt.exe)** | 33500 | **True（系統管理員身分執行）** | **被 Windows 阻擋** |

### 3. 根本原因：Windows UIPI（使用者介面權限隔離）
* **安全機制原理**：Windows Vista 以後引入的 UIPI（User Interface Privilege Isolation）機制規定：**低完整性（一般權限）程序嚴格禁止向高完整性（系統管理員權限）視窗發送任何模擬按鍵或滑鼠訊號（`keybd_event`、`SendInput`、`WM_PASTE` 等）**，防止惡意背景軟體暗中對管理員終端機下指令。
* **現象解釋**：
  * Notepad++ 是以一般權限執行，SogaType 發送的 `Ctrl + V` 順利送達。
  * 對談視窗（Windows Terminal / agy）是以「系統管理員身分」執行。SogaType 辨識完成將文字放入剪貼簿後，送出的 `Ctrl + V` 模擬鍵盤事件直接被 Windows 核心安全性防護**無聲阻擋並丟棄**。

### 4. 解決方法
* **臨時手動貼上**：在管理員視窗看到【辨識中…】消失後，直接按鍵盤實體 `Ctrl + V`，文字即可貼出（因為文字已在剪貼簿中）。
* **徹底解決（提權 SogaType）**：
  1. 結束 SogaType。
  2. 找到 `C:\Users\niceh\AppData\Local\Programs\SogaType\SogaType.exe`。
  3. 右鍵「內容」➔「相容性」➔ 勾選**「以系統管理員身分執行此程式」**。
  4. 重新啟動後，SogaType 便具備管理員權限，可穿透 UIPI 在任何終端機、管理員視窗中自動貼上。

## 附錄：SogaType「切換模式」（F9）功能解析

透過反編譯 `ActiveModes()`、`CycleMode()` 與選單邏輯，確認其功能如下：

1. **核心定位**：
   在**「AI 校正（預設）」**與**「即時多國語言翻譯」**之間進行循環切換。
2. **預設切換順序**：
   * **模式 1：AI 校正（預設）**：口說中文 ➔ 輸出整理潤飾後的繁體中文（修錯字、加標點、去贅詞）。
   * **模式 2：翻譯成 英文（en）**：口說中文 ➔ 雲端 AI 即時翻譯並貼出**英文**。
   * **模式 3：翻譯成 日文（ja）**：口說中文 ➔ 即時翻譯並貼出**日文**。
   * **模式 4：翻譯成 韓文（ko）**：口說中文 ➔ 即時翻譯並貼出**韓文**。
   * 再次按下 F9 則回到模式 1。
3. **個人化客製**：
   在 SogaType「設定…」的「翻譯語言」區塊中，僅有被勾選的語言會進入 F9 循環清單。若平常不需要日、韓文，取消勾選即可實現「AI 中文校正 ⇄ 英文翻譯」雙模式快速切換。

## 最佳實務操作總結

1. **熱鍵建議**：避開 `Ctrl + Space`（輸入法衝鍵），改用 `Alt + Space`、`Ctrl + Shift + Space` 或搭配 `Fn` 的功能鍵。
2. **權限建議**：若常在 Windows Terminal、PowerShell 管理員視窗或特定高權限 IDE 中使用語音輸入，建議將 `SogaType.exe` 設置為以系統管理員身分執行。
3. **標準輸入節奏**：
   * 先用滑鼠點擊目標文字框，**確認黑色直線輸入游標 `|` 正在閃爍**。
   * 按下錄音快捷鍵（看到【聆聽中…】提示）。
   * 正常口述語句。
   * 再次按下錄音快捷鍵（看到【辨識中…】提示）。
   * 靜候約 1 秒，文字即會自動鍵入游標所在處。
