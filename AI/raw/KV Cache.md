**KV Cache（鍵值快取）** 是大型語言模型（LLM）在進行文字生成（推論/Inference）時，用來**提升速度**與**節省運算資源**的核心技術。

如果沒有 KV Cache，LLM 在生成長文本時會越變越慢，且消耗極大的算力。

## 為什麼需要 KV Cache？（背景與痛點）

LLM（如 GPT、Llama）在生成文字時，是採用自迴歸（Autoregressive）的方式——也就是「一次只生一個字（Token）」。

當模型要生成下一個字時，它需要看過**之前所有的字**。

- **第 1 步**：輸入「今天天氣」，模型生成「很」。
    
- **第 2 步**：模型需要輸入「今天天氣很」，才能生成「好」。
    
- **第 3 步**：模型需要輸入「今天天氣很好」，才能生成「。」。
    

**痛點：**

在 Transformer 架構中，模型需要計算每個字之間的相關性（Attention 運算，包含 Key 和 Value 矩陣）。如果沒有快取，每次生成新字時，前面已經算過的舊字全部都要**重新計算一遍**。這會導致運算量隨著文字變長而呈二次方（$O(N^2)$）暴增。

## KV Cache 的工作原理

KV Cache 的邏輯很簡單：**用空間（記憶體）換取時間（算力）。**

既然前面的字都沒變，那它們對應的 **Key（鍵）** 和 **Value（值）** 矩陣也就不會變。我們把這些算好的中間結果直接存在顯存（VRAM）裡，下次就不需要重複計算了。

### 運算流程對比

|**步驟**|**沒有 KV Cache（傳統做法）**|**有 KV Cache（優化做法）**|
|---|---|---|
|**1. 提示詞處理** _(Prefill)_|計算 Prompt 中所有字的 K 和 V。|計算 Prompt 中所有字的 K 和 V，並**存入快取**。|
|**2. 生成第一個字**|計算整個序列的 Attention。|利用快取，只計算最後一個字的 Attention。|
|**3. 生成續接字** _(Decoding)_|重新計算**所有舊字 + 新字**的 K 和 V。|**只計算最新那一個字**的 K 和 V，並把新結果加進快取中。|

## KV Cache 的優缺點

### 優點

- **大幅降低延遲（Latency）：** 每次生成新 Token 的時間固定，不會因為文章變長而越生越慢。
    
- **節省計算量：** 減少了大量重複的矩陣乘法運算。
    

### 缺點與代價（顯存殺手）

KV Cache 雖然省了 CPU/GPU 算力，但非常**吃顯存（VRAM）**。

隨著上下文長度（Context Length）增加，或者並行處理的請求（Batch Size）變大，KV Cache 會吞噬極其恐怖的記憶體容量。這往往是導致大模型推論時發生 **OOM（Out of Memory，記憶體不足）** 的主要原因。

## 常見的 KV Cache 優化技術

為了解決 KV Cache 佔用太多顯存的問題，業界開發了許多優化技術：

1. **PagedAttention (vLLM)：** 仿照作業系統的「虛擬記憶體分頁」概念，把快取切成固定大小的頁面動態配置，解決記憶體碎片化問題，能節省高達 96% 的浪費。
    
2. **MQA (Multi-Query Attention) / GHA (Grouped-Query Attention)：** 讓多個 Attention Head（注意力頭）共享同一組 KV，直接從架構上將 KV Cache 的體積縮小數倍（例如 Llama 3 採用的 GQA）。
    
3. **Quantization（量化）：** 將 KV Cache 從 FP16（16位元浮點數）壓縮到 INT8 或 INT4 格式，讓同樣的顯存能裝下更多的快取。
