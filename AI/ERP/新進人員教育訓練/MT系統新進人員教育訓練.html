導讀：系統定位與閱讀指引

進口運輸管理系統（Material Trade Management System，簡稱 MT 模組） 是中鴻鋼鐵 ERP 體系中負責掌控「海外大宗原料（如扁鋼胚、合金原料、耐火材料）從國外採購、開立信用狀、海運承攬、船舶抵港卸貨、海關報關、各項進口運雜費核銷請款、到月底存貨在途原料評價估列與迴轉」的全生命週期核心營運系統。
教育訓練手冊設計目的與閱讀方針 本文件專為新進同仁量身編寫，不同於一般的簡略操作講義，本手冊從「業務流程」、「畫面操作」、「業務管制與系統防呆限制」與「技術底層程式對照」四大維度展開。新進同仁在處理使用者報修或需求變更時，請務必先查閱該作業的「管制與限制」區塊，那是日常系統維護與問題排查最頻繁碰到的關鍵核心。

技術架構分層與呼叫模式

MT 系統採用中鋼／中鴻 ICSC DPMS 傳統 Java Web MVC 框架，架構分為五層：

  • 視圖展示層（View Layer）：位於 mt/jsp/mtjj*.jsp，負責使用者畫面渲染、條件篩選輸入、分頁清單展示、JavaScript 防呆驗證及表單參數封裝。
  • 網頁控制層（Web Servlet Layer）：
    • 傳統作業：由 src/com/icsc/mt/web/mtjs*.java 繼承 HttpServlet，透過 dejc300.run() 建立 dsjccom 上下文，呼叫 mtjcWebTool.requestToInfo() 將 Request 轉換為 infoIn 雜湊表與對應 VO。
    • 新式作業：透過 config/yl/mt/mtStructs.xml 定義路由，統一經由 /erp/mt/do?_pageId=...&_action=... 由 dejcFunctionalController 進行 Action Method 動態分派。
  • 業務邏輯層（Service Layer）：位於 src/com/icsc/mt/mtjc*.java，繼承共用抽象父類 mtjcCon，負責所有資料一致性檢核、算式計算、流水號產製、資料庫交易管理（Commit / Rollback）與跨模組拋轉。
  • 資料存取層（DAO / VO Layer）：位於 src/com/icsc/mt/dao/，成對組成（如 mtjca010DAO.java 與 mtjca010VO.java），封裝 SQL 語法與 IBM DB2 資料庫表格進行實體讀寫。
  • 資料庫實體層（IBM DB2 Database）：包含 db.tbmta010 ~ db.tbmtsm010 及跨模組表格 db.tbdsdf、db.tbdsmf、db.tbdfjob。

MTPB01 系統代碼維護作業 基礎主檔 待改善

【業務用途】

集中維護 MT 系統專用之各類參數代碼與下拉選單項目。例如進口業務之「計量幣別對照」、「貿易條件（FOB/CIF/CFR）」、「付款條款類別」、「材料分類代碼」與「報關類別代碼」。透過參數化配置，避免硬編碼（Hardcoding）並確保跨模組資料標準化。

【主要功能與操作流程】
  • 階層式瀏覽與維護：畫面採主從雙層結構。先於主代碼清單頁（mtjjpb01List.jsp）檢視或新增代碼類別（如 CRCY 幣別類別、PAYM 付款方式）；再點選進入次層維護詳細代碼值（mtjjpb0102Edit.jsp）。
  • 查詢（Query）：支援依公司代碼（compId）、代碼類別（codeType）、代碼名稱模糊查詢。
  • 新增與修改（Insert / Update）：輸入代碼鍵值、中文說明、英文簡稱、排序序號（sortSeq）及是否啟用註記（useFlag: Y/N）。
  • 特定分類代碼管理：包含 mtjjpb07.jsp 獨立維護特定特殊規格代碼（對應 db.tbmtpb07）。
【管制與系統防呆限制】
  • 權限管制：需具備權限代碼 INFO_MTPB01_AUTH。非維護授權人員僅提供檢視模式，新增/修改/刪除按鈕隱藏。
  • 主鍵唯一性檢核：新增時以 compId + codeType + codeId 進行重複性檢查，若已存在則拋出提示 「該代碼已存在，請勿重複建立！」。
  • 串接引用防呆刪除管制：若某代碼已於信用狀主檔（tbmta010）、船運主檔（tbmtb010）或費用報支檔（tbmtfc030）中被記錄引用，系統後端強制攔截刪除（拋出 FK Constraint / 該代碼已被業務單據使用，禁止刪除！）。僅允許修改為停用狀態（useFlag='N'）。
  • 階層級聯管制：欲刪除主代碼類別（tbmtpb010）時，必須先確認其底下之明細子代碼（tbmtpb020）已全數刪除，不可懸空殘留孤立資料。
【不妥之處／建議調整】
  • XML 路由配置缺檔與架構分裂（中）：config/yl/mt/mtStructs.xml:14-25 定義了 com.icsc.mt.mtjcpb010 與 mtjcpb020 控制器，但 src/ 目錄下無此類別，實際全走 mtjspb01.java 舊 Servlet 模式呼叫 mtjcpb01.java。建議日後改版時清理 XML 殘留設定，或將 Controller 補齊以統一現代架構。
  • 輸入欄位未設定長度限制（低）：jsp/mtjjpb0101Edit.jsp:45 與 mtjjpb0102Edit.jsp:52 之文字輸入框僅設定 size 而漏設 maxlength，使用者若貼入過長字串將在後端寫入 DB2 時引發欄位長度溢位異常（SQLCODE=-302）。建議補上 maxlength="20"。
  • 刪除例外包裝不足（中）：mtjcpb01.java:112 刪除主檔代碼時，若遇到子表外鍵限制，僅列印 e.printStackTrace() 並回傳通用錯誤代碼，未將具體「被哪張子表引用」轉化為友善中文訊息告知使用者。

MTFC01 費用類別維護作業 費用基礎 待改善

  • 費率明細維護（mtjjfc0102Edit.jsp）：維護每種費用之計費基數（依重量計、依櫃數計、依提單計、固定費率）、預設廠商代號及對應之會計科目（如進口在途雜費科目）。
  • 附加費率階梯設定（tbmtfc025）：支援不同批量噸位或港口區域之差別費率定義。
【管制與系統防呆限制】
  • 權限管制：需具備 INFO_MTFC01_AUTH 權限，財務與採購主管方可配置。
  • 請款單據鎖定防呆：此作業之費用代號為後續「一般報支（MTFC03）」、「借支（MTFC04）」及「運雜費清單（MTFC02）」之下拉來源。一旦該費用代號已有請款或拋轉 AP 記錄，禁止變更費用代碼與會計科目，避免歷史會計帳目勾稽混亂。
  • 稅額類別一致性管制：設定之課稅別（如應稅 5%）必須符合稅法規範，若標記為零稅率，需於備註中註明外銷或保稅海運條款。

  • SQL 動態拼接風險（高）：src/com/icsc/mt/mtjcfc01.java:85 於 querySingle() 中，直接使用 "where fee_code = '" + feeCode + "'" 字串拼接組裝 SQL 查詢，未採用 PreparedStatement 參數化查詢，存在潛在 SQL Injection 風險與 DB2 Dynamic Statement Cache 效能命中率降低之問題。

  • 會計科目缺乏即時存在性防呆（中）：jsp/mtjjfc0102Edit.jsp:68 允許使用者直接手動鍵入借方會計科目代碼，但畫面未提供即時彈窗核對會計總帳科目檔（GL Account），導致使用者可能輸錯無效科目，延遲到 MTFC03 報支拋轉 AP 時才報錯退件。

MTE01 費用公式維護作業 公式計算 待改善

【業務用途】

設定進口運雜費之各項自動試算公式與運算邏輯。例如依據採購合約金額自動計算「海上保險費率（Marine Insurance Rate）」、「商港建設服務費率（0.04%）」、「貿易推廣服務費率（0.0415%）」或依鋼胚淨重比例自動計算公分攤雜費。

【主要功能與操作流程】
  • 公式清單查詢（mtjje01List.jsp）：依公式代號、有效年度、材料分類搜尋適用之計算公式。
  • 公式規則維護（mtjje01Edit.jsp）：設定運算符號、固定加成率、費率乘數、最低起算金額與捨入小數點位數（Round / Floor / Ceil）。
  • 版本生效日期控管：支援「生效日期（startDate）」與「失效日期（endDate）」，以符合法規費率隨時點調整之需求。
【管制與系統防呆限制】
  • 權限管制：需具備 INFO_MTE01_AUTH。
  • 日期區間重疊防呆：同一費用項目之生效起訖區間不可與歷史版本重疊，避免後端自動試算時發生一對多衝突（Ambiguous Formula Error）。
  • 數值除零與負數檢核：公式之分母或計算比例禁止為 0 或負數，輸入時前端 JavaScript 與後端 mtjce01.java 均會進行嚴格合法性校驗。

會計部（A21）專責月結作業。於每月會計結帳日前，依據當月產量與權利金合約費率，自動產生「權利金預估估列傳票（Accrual Voucher: 借-權利金費用 / 貸-應付費用-預估）」；次月初結帳時，系統自動產生「實際迴轉傳票（Reversal Voucher: 借-應付費用-預估 / 貸-權利金費用）」，確保損益表各月負擔合理平衡。

【主要功能與操作流程】
  • 主查詢與條件設定（mtjjCom01.jsp / mtjjCom01Edit.jsp）： 輸入公司代碼（compId）、成本類別（costType）、資料年月（dataYm: YYYYMM）、關帳基準日期。
  • 標準會計傳票動作按鈕：
    • createE (動作旗標 E)：自動計算當月預估權利金，產製並寫入「預估傳票檔（Accrual Voucher）」。
    • createR (動作旗標 R)：產生次月之「迴轉傳票檔（Reversal Voucher）」。
    • RR：重新整理與重建該月計算資料。
    • cancelE：撤銷已產生之預估傳票（限傳票尚未拋轉總帳前）。
    • cancelR：撤銷已產生之迴轉傳票。
    • PR1：列印該期權利金估列與迴轉試算平衡報表。
【管制與系統防呆限制】
  • 權限管制：需具備專屬權限 INFO_MTJJCOM01_AUTH，主要授權為會計處成本會計組（A21）。
  • 時序依存防呆限制： 【重要管制】必須先成功執行 createE 產生估列傳票後，次月才允許執行 createR 產生迴轉傳票！若該年月無估列資料，直接點擊迴轉將遭系統攔截：「尚未產生預估傳票，無法執行迴轉作業！」。
  • 傳票過帳後不可撤銷管制： 若預估傳票或迴轉傳票已經會計總帳模組（GL）正式審核過帳（Posted），cancelE 與 cancelR 按鈕立即失能禁用，禁止私自撤銷已入帳之會計傳票。
  • 跨期資料不可逆防呆：歷史已完成過帳之舊年月資料僅能查詢瀏覽，不可手動修改數值。
【不妥之處／建議調整】
  • 分攤估列比率硬寫於 Java 程式碼（中）：src/com/icsc/mt/mtjcCom01CR.java:110 計算各部門產品權利金估列金額時，部分分攤比例係數直接寫死於 Controller 程式碼中。若技術合約修改拆帳比例，必須由資訊人員修改 Java 原始碼重編發布，缺乏維護彈性。建議改至 db.tbmtCom01 或參數主檔維護。

第十章：國內外在途原料估列、迴轉作業（選單節點 MTJJRAW01）

進口大宗鋼胚金額極為龐大，一艘貨輪鋼胚價值動輒數億台幣。當貨物在公海航行（在途）或已開立信用狀但尚未通關入廠時，會計部必須於月底將此部分資產與負債正確估列入帳。本作業為存貨會計每月結帳不可或缺之重裝級作業。

MTJJRAW01 國內外在途原料估列、迴轉作業 在途存貨 月結傳票 2024基期限制 待改善

【業務用途】

會計部（A21）於每月最後營業日執行。整合船運主檔（tbmtb010）、信用狀（tbmta010）與採購合約（tbmtp010），精準計算「已開狀但尚未到港」及「已到港但尚未報關驗放」之國內外在途原料（Goods in Transit）價值。月底自動開立「在途原料估列傳票（借-在途原料 / 貸-暫估應付款）」；次月初再開立「反向迴轉傳票」，使存貨與負債精準符合 IFRS 會計準則。

【主要功能與操作流程】
  • 估列條件輸入（mtjjRaw01.jsp / mtjjRaw01Edit.jsp）： 輸入公司代碼（compId: yl）、成本類別（原料類）、結算年月（dataYm）及結算基準日期（通常為月底日）。
  • 自動勾稽在途庫存： 系統後端自動掃描：
    1. 裝船日 onBoardDate ≤ 結算日，且海關放行日大於結算日（或尚未放行）之所有進口船次。
    2. 已開立信用狀且已押匯、但尚未取得正式驗收單之材料合約。
  • 核心動作按鈕：
    • createE：產製本月在途原料預估傳票及報表。
    • createR：產製次月迴轉傳票。
    • cancelE / cancelR：取消估列或迴轉傳票（需主管確認）。
    • PR1：列印在途原料明細清冊與會計勾稽表。
【管制與系統防呆限制】
  • 權限管制：需具備 INFO_MTJJRAW01_AUTH，限會計處特定月結負責人（A21）操作。
  • 歷史資料保護基期限制（limitDate 20240101）： 【極重要程式硬性管制】在後端控制器 mtjcRaw01CR.java 中，明確定義硬性常數 limitDate = "20240101"！系統嚴格禁止對 2024 年 1 月 1 日以前之歷史在途資料進行重新計算、修改或撤銷傳票，保護歷年已通過外部會計師查核之財務歷史結帳基期！
  • 在途與到庫重複認列防呆： 若某船次之海關放行日期在月底結算日前，代表該原料已辦理報關並正式入庫（存貨已計入現場倉儲），系統邏輯強制將其排除在「在途原料」之外，防範同一批鋼胚被雙重認列（Double Counting）。
  • 關帳順序管制：在途原料估列完成並產生傳票後，會計部方可執行全廠「存貨系統總關帳」；存貨總關帳後，禁止在 MTJJRAW01 執行 cancelE。

  • limitDate 日期硬編碼維護不易（中）：src/com/icsc/mt/mtjcRaw01CR.java:82 直接寫死 limitDate = "20240101"。未來若隨年度推進需要變更結算封存基期（例如邁入 2027 年需封存 2025 年前資料），必須由維護人員重新修改 Java 程式編譯並重啟 Web 服務。建議將此日期抽離為資料庫系統參數或組態檔配置。
  • 傳票產製缺乏預覽確認步驟（中）：點擊 createE 後系統直接生成正式會計預估傳票，若同仁輸入錯誤之基準日，必須多走一次 cancelE 撤銷流程。建議比照現代 ERP 設計，提供「試算預覽（Preview / Dry-Run）」模式，先檢視明細金額無誤後再按確認開立傳票。
