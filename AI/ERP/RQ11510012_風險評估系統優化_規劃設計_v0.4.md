1. **新增**（`doInsert`）：formNo＝RECode 去首碼＋dept(4)＋年(2)＋日序(3)＋時分(4)，共 18 碼；建立 WorkDoc（C1、reportID 0001、docStatus F）。**目前沒有任何前版檢核**。

3. **風險評估簽核完成（0001/E）** → 進入【風險與機會評估】時 `eajcRE13CRN.update()` 把 WorkDoc 改為 reportID 0002、docStatus F；**0002/E＝風險與機會評估簽核完成**。

## 3. 功能設計

### 3.1 R1：新增風險評估之版次管控（`eajcRE00CRN.doInsert()`）

**規則**：系統日 ≥ 版次管控生效日（系統參數）時，新增前檢查同部門所有風險評估：

```sql
-- 有任一筆回傳即不可新增
SELECT A.FORMNO, W.REPORTID, W.DOCSTATUS
FROM DB.TBEARE00 A
JOIN DB.TBEAWORKDOC W ON W.WORKDOCID = A.FORMNO
WHERE A.COMPID = ? AND A.DEPT = ?            -- 不分 RECode 的 Y/S（年度、偶發一起管控）
  AND NOT (W.REPORTID = '0002' AND W.DOCSTATUS = 'E')
  AND A.FORMNO >= ?                           -- 待確認：歷史資料的排除條件（見 Q1）
```

- 不符合時訊息：「部門 ○○ 尚有【風險與機會評估】未簽核完成或尚未進入機會階段（文號：…），需全部簽核完成才可新增【風險評估】」。
- 不檢查高風險（RE04）簽核狀態。
- 版次管控生效日以系統參數保存（`eajcSQ.getSystemPara(dsCom,"RE_VERCTL_DATE")`，參數名待定），避免寫死。
- 建議前端（`eajjRE00MainN.jsp`）同步檢查，不符合時「新增」按鈕 disabled 並顯示原因（可選）。

> 2026-10-08 使用者補充指示：在原【複製】旁增加【新版複製】，依照「最新B表匯出」的 SQL 抓法，並參考【複製】功能的動作；**關聯文件編號（REFNO）要留下紀錄**，以便追蹤新評估編號每一項的原始依據；REFNO 開頭為 **HC-** 者，除了要複製該高風險文號的**高風險改善追蹤異動資料**，也要執行 (EAJJRE20N) 高風險改善追蹤的**【預估評估】**動作。

> v0.4：關聯文件編號改存 `tbeaRE03` 新欄位（3.3.3），不再寫 `tbeaWorkDocEX`。

**做法**：不用 `INSERT … SELECT` 一次寫入，改為「用最新B表 SQL 取出每一列（含 REFNO），再由 Java 逐列處理」，因為每一列要依 REFNO 類型做不同的動作。

#### 3.3.1 共用 SQL 調整（`eajcRERpt`）

把 `exportLatestB()` 的 SQL 抽成 `getLatestBSql(compId, dept)`，讓匯出與新版複製共用。複製用的版本要**多帶出鍵值與文號欄位**（匯出時不輸出這些欄位即可）：

| 加帶欄位 | 來源 | 用途 |
|---|---|---|
| FROMFORMNO | B.FORMNO（LATEST_RA） | 來源評估文號 |
| FLOW0CODE、FLOW1CODE、SRLNO | B.* | 寫入新 RE03 的鍵（不要從 KEYNO 字串拆） |
| REFTYPE | RA／HR／HC／RO | 寫入 `RE03.refType`，並判斷處理方式 |
| REFDOCNO | HR、HC＝高風險文號；RA、RO＝來源評估文號 | 寫入 `RE03.refDocNo` |
| HRVERSDATE | HD／HA 的 VERSDATE | HC 移轉時參考（核准時會重新讀取，3.4.2） |

> 注意：`exportLatestB` 用 `dejcQueryDAO`，因為 `zafcDAO` 不接受 `WITH` 開頭的 SQL。

#### 3.3.2 處理步驟（單一交易）

1. **檢核**
   - 目標 formNo 的 vers 必須為空（未確認），沿用 `doCopy()` 的檢核。
   - 操作者必須是目標版的建立者（`doEstimate` 也有同樣限制）。
   - 用 `getLatestBSql()` 取得 LATEST_RA；查無時提示「無已簽核完成之【風險與機會評估】可複製」。
2. **清除目標**：`removeByFormNo` RE01、RE02、RE03（同 `doCopy`）。追蹤資料在 RE03 上，**刪 RE03 就一起清掉**，不用另外處理。方案 B 下新版複製階段不會產生 RE04／RE042／RE043／高風險文號（且目標版未簽核前 `isCanExecuteHrisk()` 也擋住手動預估評估），所以不需要清除高風險資料。
3. **複製 RE01、RE02**：沿用 `copyByFormNo(compId, fromFormNo, toFormNo)`。
4. **逐列處理最新B表結果**，每列以新 DAO（19 欄）`create()` 寫入 RE03：

| REFTYPE | RE03（7 欄） | `refType`／`refDocNo` | `hcTransDate` | 其他動作 |
|---|---|---|---|---|
| RA | 來源原值 | RA／來源評估文號 | 空白 | — |
| RO | RE13 的 7 欄（D／I） | RO／來源評估文號 | 空白 | — |
| HR | 前 3 欄＝RE04、後 4 欄＝RE042 status 30 | HR／高風險文號 | 空白 | — |
| HC | 來源原值（仍為等級 1、2） | HC／舊高風險文號 | 空白（待核准時寫入） | **見 3.4：核准時複製異動資料＋執行預估評估** |

5. **不鎖定**：複製後 RE01～03 仍可自行修改；新欄位由程式維護，畫面不提供修改。
6. 訊息：「新版複製完成！來源文號 ○○；流程 n、A 表 n、B 表 n 筆（RA n／RO n／HR n／HC n）；HC n 筆將於風險評估核准後自動移轉高風險追蹤」。

#### 3.3.3 關聯文件編號寫入 `tbeaRE03` 新欄位

追蹤資料本質上是「B 表每一列的原始依據」，和 RE03 是**一對一**，所以直接存在 RE03 上，跟著 B 表一起新增、修改、刪除。

**新增欄位**

| 欄位 | 型態 | 預設 | 內容 |
|---|---|---|---|
| `refType` | VARCHAR(2) | `''` | 關聯類型：RA／HR／HC／RO；空白＝非新版複製產生（一般新增、原「複製」、CSV 匯入） |
| `refDocNo` | VARCHAR(40) | `''` | 關聯文件編號：HR／HC＝舊高風險文號；RA／RO＝來源評估文號 |
| `hcTransDate` | VARCHAR(8) | `''` | HC 移轉完成時寫入核准日（yyyymmdd）；空白＝尚未移轉。兼作防止重複移轉的旗標；新高風險文號可由新鍵＋此日期用 `queryWorkDocEX()` 反查 |

- 寬度依據：高風險文號 28～31 碼、評估文號 18 碼，40 碼與 `tbeaWorkDocEX.WorkDocID` 同寬。
- 日期沿用 ERP 慣例存 8 碼字串。
- 寫法沿用 `db.tbeaRE03.sql` 既有風格：`NOT NULL WITH DEFAULT ''`，舊資料自動為空白，不會有 null。
- flow1Code 有尾端空白（3.4.7），`refDocNo` 存放舊高風險文號時**原樣保存、不可 trim**。

```sql
-- RQ11510012：新版複製追蹤欄位
ALTER TABLE db.tbeaRE03
  ADD COLUMN refType     VARCHAR(2)  NOT NULL WITH DEFAULT ''
  ADD COLUMN refDocNo    VARCHAR(40) NOT NULL WITH DEFAULT ''
  ADD COLUMN hcTransDate VARCHAR(8)  NOT NULL WITH DEFAULT '';
```

- 新欄位會加在資料表最後面（RANK 之後），不影響既有欄位順序；主鍵不變。
- 權限：既有 `GRANT … TO USER JAVAUSER` 是針對整張資料表，加欄位後應不用重新授權（Q-B2）。
- 索引：B2 鎖定檢查要「用舊高風險文號反查新 formNo」，會依 `refDocNo` 跨單查詢。**2026-10-13 查正式機（Q-B4）：RE03 共 1,309,777 筆、2,805 個 formNo；現有索引只有主鍵 `(compId, formNo, flow0Code, flow1Code, srlNo)`**。B2 的條件沒有 formNo，用不到主鍵，不加索引的話每次開高風險畫面都要掃一百三十萬筆，所以**必須加索引**，和 ALTER 一起放進 `db.tbeaRE03_RQ11510012.sql`：
  ```sql
  CREATE INDEX db.ixeaRE03_ref ON db.tbeaRE03 (refDocNo, refType);
  ```
  `refDocNo` 放前面：舊資料都是空白，有值的只有新版複製產生的列，選擇性高；`refType` 只有四種值，放後面。B10 的核准筆數提示有帶 formNo，走主鍵就夠了。

**回退 DDL**（不得已才用）

```sql
ALTER TABLE db.tbeaRE03 DROP COLUMN hcTransDate DROP COLUMN refDocNo DROP COLUMN refType;
-- DB2 LUW 執行 DROP COLUMN 後資料表會進入 REORG pending，需要再執行：
-- CALL SYSPROC.ADMIN_CMD('REORG TABLE db.tbeaRE03');
```

**第一段：新版複製時（`doCopyLatest()`）**

#### 3.4.6 既有 bug：`getWorkDocNumber()` 跨序號取號

`No＝formNo＋flow0＋flow1＋srlNo`（srlNo 不補零），以 `WORKDOCID LIKE 'No%' ORDER BY WORKDOCID DESC` 取最大號：
- srlNo＝1 的 `LIKE 'X1%'` 也會比對到 srlNo＝12 的 `X12001`；`replaceAll("X1","")` 得 `2001`，加 1 後產生 `X12002`，日後 srlNo＝12 要取 002 時就撞號。
- `catch (Exception)` 一律回傳 `001`，把錯誤吃掉，最後變成主鍵重複。
- 同一張單同時有 srlNo＝1 與 10～19（或 100 以上）的高風險項目就可能發生；方案 B 在核准時一次替多筆 HC 取號，機率更高。

修正建議（**不改**現有文號格式）：改從 `TBEAWORKDOCEX` 取號——`field1～4＝鍵`、`field5<>''`，取最大號後用固定長度 `substr` 取最後 3 碼加 1。（v0.3 的 `WorkDocID NOT LIKE 'CP%'` 條件在 v0.4 不需要，WorkDocEX 裡不會有追蹤列。）

## 5. 上線步驟與順序（v0.4 新增）

`copyByFormNo()`、`doImport()` 等沒寫欄位清單的 INSERT（3.6.1）在 ALTER 後會壞，而重新產生的 DAO 又只能在 ALTER 後部署，所以**建議兩段式上線**（Q-B7）：

| 階段 | 步驟 | 動作 | 環境 |
|---|---|---|---|
| 第一次上線（過渡版） | 1 | 只改 3.6.1 三處 INSERT 補欄位清單（不加欄位、不含新功能） | 測試機 |
| | 2 | 測試 T-B5（複製、匯入、維護功能和上線前一樣） | 測試機 |
| | 3 | CVS 提交、DAJJU1 上線申請、上線 | 正式機 |
| 第二次上線（新功能） | 4 | 測試機執行 ALTER（3.3.3） | 測試機 |
| | 5 | 改 `.dao`、daotool 重新產生、搬回手寫方法；實作第 3 節 | 測試機 |
| | 6 | 測試 T1～T12、T-B1～T-B4 | 測試機 |
| | 7 | CVS 提交（含 `db.tbeaRE03_RQ11510012.sql`）；依公司程序申請正式機 DDL（Q-B1） | — |
| | 8 | DAJJU1 上線申請，上線說明註明「需先執行 DDL」 | — |
| | 9 | 上線當天：**先**執行正式機 ALTER → 確認欄位存在 → **再**部署程式 | 正式機 |
| | 10 | 上線後驗證：原「複製」、B 表匯入、B 表維護、新版複製各操作一次 | 正式機 |

- 兩段式的好處：第一次上線後，ALTER 前後舊程式都能正常運作，第二次上線沒有「ALTER 完成到程式部署完成之間複製、匯入會失敗」的風險窗口。
- 若不採兩段式（一次上線），步驟 9 必須選在使用者不操作的時段，並盡量縮短 ALTER 與部署之間的時間。

**回退方案**

| 狀況 | 處理 |
|---|---|
| ALTER 失敗 | 不部署第二次上線的程式，過渡版照常運作 |
| 第二次上線後有問題 | 還原成**過渡版**程式並保留欄位（過渡版不受新欄位影響）；**不可**還原成第一次上線前的舊版。不得已時才執行回退 DDL |

## 10. 附錄 A：新版複製 RE03 SQL 初稿（未在 DB 執行過）

> 新版複製已改為「最新B表 SQL 取出每一列＋Java 逐列處理」（3.3.1），本節 INSERT … SELECT 只保留作為覆蓋邏輯參考與驗證比對用。**v0.4 加欄位後，INSERT 必須補上 16 欄的欄位清單**（3.6.1）；若要直接用本 SQL 寫入，另需帶出 refType／refDocNo。

參數：`:compId`、`:fromFormNo`（LATEST_RA 查出的文號）、`:toFormNo`（新版文號）。
RE03 欄位順序依 `eajcRE03DAO.copyByFormNo()`：COMPID, FORMNO, FLOW0CODE, FLOW1CODE, SRLNO, PROCEDURE, REASON, EFFECT, ACCIDENTTYPE, CONSTRUCTCTRL, MANAGECTRL, EQUIPMENTCTRL, EXPOSE, FREQUENCE, SEVERITY, RANK。
與最新B表差異：不需要 RE01／RE02 的 join（只匯出才要 FLOWNAME／WORKSTUS），也不需要 ROW_NUMBER 收斂 RE02。

```sql
INSERT INTO DB.TBEARE03
  (COMPID, FORMNO, FLOW0CODE, FLOW1CODE, SRLNO, PROCEDURE, REASON, EFFECT, ACCIDENTTYPE,
   CONSTRUCTCTRL, MANAGECTRL, EQUIPMENTCTRL, EXPOSE, FREQUENCE, SEVERITY, RANK)
WITH HR_LATEST AS (
  SELECT X.* FROM (
    SELECT H.COMPID, H.FORMNO, H.FLOW0CODE, H.FLOW1CODE, H.SRLNO, H.VERSDATE,
           H.CONSTRUCTCTRL, H.MANAGECTRL, H.EQUIPMENTCTRL,
           EX.WORKDOCID AS HRDOCNO, HW.DOCSTATUS AS HRDOCSTATUS,
           ROW_NUMBER() OVER (PARTITION BY H.COMPID,H.FORMNO,H.FLOW0CODE,H.FLOW1CODE,H.SRLNO
                              ORDER BY H.VERSDATE DESC, EX.WORKDOCID DESC) AS SN
    FROM DB.TBEARE04 H
    LEFT JOIN (SELECT FIELD1,FIELD2,FIELD3,FIELD4,FIELD5,MAX(WORKDOCID) AS WORKDOCID
               FROM DB.TBEAWORKDOCEX GROUP BY FIELD1,FIELD2,FIELD3,FIELD4,FIELD5) EX
      ON EX.FIELD1=H.FORMNO AND EX.FIELD2=H.FLOW0CODE AND EX.FIELD3=H.FLOW1CODE
     AND EX.FIELD4=H.SRLNO AND EX.FIELD5=H.VERSDATE      -- TODO: FIELD4 型別（exWD 用 int(field4)）
    LEFT JOIN DB.TBEAWORKDOC HW ON HW.WORKDOCID = EX.WORKDOCID
    WHERE H.COMPID = :compId AND H.FORMNO = :fromFormNo
  ) X WHERE X.SN = 1
),
HR_DONE AS (
  SELECT H.*, E.EXPOSE AS E_EXPOSE, E.FREQUENCE AS E_FREQUENCE,
         E.SEVERITY AS E_SEVERITY, E.RANK AS E_RANK
  FROM HR_LATEST H
  JOIN (SELECT Y.* FROM (
          SELECT E.*, ROW_NUMBER() OVER (
                   PARTITION BY E.COMPID,E.FORMNO,E.FLOW0CODE,E.FLOW1CODE,E.SRLNO,E.VERSDATE
                   ORDER BY E.EXPWDATE DESC, E.ACTEDATE DESC) AS SN
          FROM DB.TBEARE042 E
          WHERE E.COMPID = :compId AND E.FORMNO = :fromFormNo AND E.STATUSCODE = '30'
        ) Y WHERE Y.SN = 1) E
    ON E.COMPID=H.COMPID AND E.FORMNO=H.FORMNO AND E.FLOW0CODE=H.FLOW0CODE
   AND E.FLOW1CODE=H.FLOW1CODE AND E.SRLNO=H.SRLNO AND E.VERSDATE=H.VERSDATE
  WHERE H.HRDOCSTATUS = 'E'
),
RO AS (
  SELECT X.* FROM (
    SELECT O.*, ROW_NUMBER() OVER (PARTITION BY O.COMPID,O.FORMNO,O.FLOW0CODE,O.FLOW1CODE,O.SRLNO
                                   ORDER BY O.FORMNO) AS SN
    FROM DB.TBEARE13 O
    WHERE O.COMPID = :compId AND O.FORMNO = :fromFormNo AND O.IMETHOD IN ('D','I')
  ) X WHERE X.SN = 1
)
SELECT B.COMPID, :toFormNo, B.FLOW0CODE, B.FLOW1CODE, B.SRLNO,
       B.PROCEDURE, B.REASON, B.EFFECT, B.ACCIDENTTYPE,
       COALESCE(HD.CONSTRUCTCTRL, CASE WHEN B.RANK NOT IN ('1','2') THEN O.CONSTRUCTCTRL END, B.CONSTRUCTCTRL),
       COALESCE(HD.MANAGECTRL,    CASE WHEN B.RANK NOT IN ('1','2') THEN O.MANAGECTRL    END, B.MANAGECTRL),
       COALESCE(HD.EQUIPMENTCTRL, CASE WHEN B.RANK NOT IN ('1','2') THEN O.EQUIPMENTCTRL END, B.EQUIPMENTCTRL),
       COALESCE(HD.E_EXPOSE,      CASE WHEN B.RANK NOT IN ('1','2') THEN O.EXPOSE        END, B.EXPOSE),
       COALESCE(HD.E_FREQUENCE,   CASE WHEN B.RANK NOT IN ('1','2') THEN O.FREQUENCE     END, B.FREQUENCE),
       COALESCE(HD.E_SEVERITY,    CASE WHEN B.RANK NOT IN ('1','2') THEN O.SEVERITY      END, B.SEVERITY),
       COALESCE(HD.E_RANK,        CASE WHEN B.RANK NOT IN ('1','2') THEN O.RANK          END, B.RANK)
FROM DB.TBEARE03 B
LEFT JOIN HR_DONE HD
  ON HD.COMPID=B.COMPID AND HD.FORMNO=B.FORMNO AND HD.FLOW0CODE=B.FLOW0CODE
 AND HD.FLOW1CODE=B.FLOW1CODE AND HD.SRLNO=B.SRLNO AND B.RANK IN ('1','2')
LEFT JOIN RO O
  ON O.COMPID=B.COMPID AND O.FORMNO=B.FORMNO AND O.FLOW0CODE=B.FLOW0CODE
 AND O.FLOW1CODE=B.FLOW1CODE AND B.SRLNO = INTEGER(TRIM(O.SRLNO)) AND B.RANK NOT IN ('1','2')
WHERE B.COMPID = :compId AND B.FORMNO = :fromFormNo
```

待驗證：
- DB2 是否接受 `INSERT INTO … (欄位清單) WITH … SELECT`（DB2 LUW 可以；若不行改成 Java 先 `dejcQueryDAO.getDatas()` 撈出再逐筆 create）。
- `B.RANK` 為 NULL 時 `NOT IN ('1','2')` 為 unknown，該列不會套機會覆蓋；最新B表已上線的寫法相同，兩邊結果一致，但需確認業務上是否要 `COALESCE(B.RANK,'')`。
