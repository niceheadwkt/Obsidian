# 入庫（wiki-ingest）

本 skill 是 [AI/schema.md](../../../AI/schema.md) 匯入流程的執行版。格式規範（frontmatter、連結語法、衝突警示）以 schema.md 為準，這裡只寫步驟與品質標準。

工具腳本：`python AI/scripts/wiki_tool.py`（在 vault 根目錄 `G:/我的雲端硬碟/Obsidian` 執行）。

## 步驟

### 1. 找出要入庫的素材
- 使用者有指定檔案就用指定的。
- 只說「入庫」時，執行 `python AI/scripts/wiki_tool.py pending`，列出尚未被 Wiki 引用的素材，請使用者挑選；清單很長時建議**一次一篇**（Karpathy 建議初期逐篇、保持參與）。
- `raw/`、`sources/` 是唯讀，不修改原始內容。

### 2. 閱讀素材
- 完整閱讀。剪輯檔常在後段夾帶無關文章（例如網站推薦文），**只處理主文**，並在 log 註明略過了什麼。
- 檢查 frontmatter 的 `source` 網址和內容是否相符，不符時在頁面註明。
- 英文素材若是瀏覽器機器翻譯（例：agent 被翻成「代理商」），以原意修正用詞。

### 3. 和使用者確認重點
- 列出：一句話重點（30 字內）、三到五個要點、預計新建或更新哪些頁面。
- 等使用者確認或補充後再寫入。使用者明說「不用確認」或批次模式時可略過，但最後回報要完整。

### 4. 先查重，再決定新建或擴充（避免重複頁）
- 讀 `AI/wiki/index.md`，並用 Grep 在 `AI/wiki/` 搜尋素材的關鍵實體、工具名稱。
- 主題已有頁面 → **擴充舊頁**（新增章節、補 sources、更新 updated），不要另開相近的新頁。
- 只有在新主題、或內容足以獨立成篇時才新建。素材提到的工具／人物／產品若已有實體頁，一併更新該頁。

### 5. 撰寫頁面
新建頁面依頁面類型套用下列結構（自 2026-11-18 起的新頁必須遵守，評分腳本會檢查）：

```markdown
---
type: source-summary            # concept / entity / source-summary / analysis
tags: [標籤1, 標籤2]
sources: ["[[AI/raw/原始檔名.md|顯示名稱]]"]
created: YYYY-MM-DD
updated: YYYY-MM-DD
---

# 頁面標題

一兩句說明來源（作者、媒體、日期）與這篇在講什麼。

**一句話重點**：寫結論而非主題，30 字以內

## 一、……（主體內容，依素材組織）

## 我可以怎麼用
- 對照使用者的工作（ERP 規劃設計、AI 工具實務、知識庫維護）寫出具體可行的用法。

## 關聯頁面
- [[相關頁面 A]]
- [[相關頁面 B]]
```

- `source-summary`、`analysis` 必須有「**一句話重點**：」行；所有新頁都要有「我可以怎麼用」段落。
- 擴充舊頁時不強制補這兩段，但若舊頁沒有「我可以怎麼用」，可順手補上。

### 6. 雙向連結與衝突
- **連結一律用 `[[頁面名稱]]`，不要包在反引號裡**（反引號內在 Obsidian 不算連結，關係圖不會有線）。
- 新頁至少連到一篇舊頁；同時**回頭修改至少一篇相關舊頁**，在其「關聯頁面」或內文加上指回新頁的連結。
- 新內容和舊頁說法衝突時，在相關頁面加：
  ```markdown
  > [!WARNING] 內容衝突
  > 根據 [[來源 A]] 指出……；但 [[來源 B]] 指出……
  ```
  **只標出、不替使用者下結論**，回報時列出待使用者決定的衝突。

### 7. 更新 index 與 log
- `AI/wiki/index.md`：在正確區塊新增或更新一列（概念與分析／實體與工具／原始文獻目錄）；來源編號接續目前最大的 `SRC-xxx`。index 既有慣例是把連結包在反引號內，沿用即可。
- `AI/wiki/log.md` 末尾追加：

```markdown
## [YYYY-MM-DD] ingest | 來源標題

- **來源**：`raw/檔名.md`。作者／媒體／日期。略過的無關內容。
- **新增頁面**：`[[頁面]]`（type）：內容摘要。
- **更新頁面**：`[[頁面]]`（改了什麼）。
- **更新索引**：新增／更新哪幾列，新增 `SRC-xxx`。
- **執行人**：Claude Code
```

### 8. 自我評分（必做）
```bash
python AI/scripts/wiki_tool.py check "新頁名稱" "更新的頁名稱" ...
```
- 任何 `FAIL` 都要自己修正後重跑，直到 FAIL 為 0。`WARN` 視情況處理。
- 檢查項目：frontmatter 齊全、type 合法、sources 存在、至少連一篇舊頁、無斷鏈、有舊頁回連（雙向）、已列入 index、log 有記錄；新頁另查一句話重點 ≤ 30 字與「我可以怎麼用」。

### 9. 回報
簡短回報：處理了哪篇、新增／更新哪些頁、評分結果、待使用者決定的衝突、`pending` 剩餘篇數。

## 被糾正時
使用者對成品提出修正（例如重點太長、要點太空泛），除了改這一篇，也要問是否把規則寫回本 SKILL.md，讓之後每一篇都照做。
