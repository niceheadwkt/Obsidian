# Wiki 健檢（wiki-lint）

本 skill 是 [AI/schema.md](../../../AI/schema.md) 檢查流程的執行版。機械性檢查交給腳本，AI 只做需要判斷的部分，節省 token。

## 步驟

### 1. 跑腳本取得報告
```bash
python AI/scripts/wiki_tool.py lint              # 預設 120 天未更新視為可能過時
python AI/scripts/wiki_tool.py lint --stale-days 90
```
報告項目：斷鏈、多次被提到卻沒有頁面的目標、包在反引號裡的連結、孤立頁、未列入 index、frontmatter 問題、過時頁、現有衝突標記、raw 未匯入數、樞紐頁面。

### 2. AI 判讀（腳本做不到的部分）
- **反引號連結**：判斷哪些是真的要連（應移除反引號），哪些是示範語法（例如 `[[雙括號]]`、`[[頁面名稱]]`，保留）。
- **孤立頁**：找出應該連向它的頁面（看主題、tags），提出要加連結的位置。
- **過時頁**：抽看內容，若有版本、價格、模型名稱等時效性資訊，建議查證或標記；不要只因日期舊就改。
- **衝突標記**：列出各頁仍未處理的 `[!WARNING]`，請使用者逐一決定，不自行下結論。
- **缺少頁面的概念**：從斷鏈與多頁重複提到的名詞，建議值得獨立成頁的概念或實體。
- **知識缺口**：依樞紐頁與 `pending` 素材，建議下一步要入庫的素材、可以上網補的主題、值得研究的新問題。

### 3. 回報並請使用者決定
用結構化摘要回報：可自動修的（斷鏈、反引號連結、補回連、補 index）與需要使用者決定的（衝突、刪併頁面、過時內容）。**修改前先取得同意**；項目多時可分批。

### 4. 修復
- 依同意範圍修改，連結一律用 `[[頁面名稱]]`，不包反引號（index.md 例外，沿用既有表格慣例）。
- 修改過的頁面更新 `updated` 日期。
- 修完重跑 `python AI/scripts/wiki_tool.py lint` 確認數字下降；有改到內容的頁面可用 `check` 驗證。

### 5. 寫入 log
`AI/wiki/log.md` 末尾追加：

```markdown
## [YYYY-MM-DD] lint | 本次健檢主題

- **發現**：斷鏈 N、孤立頁 N、反引號連結 N、未匯入素材 N……
- **已修復**：……
- **待決定**：……
- **執行人**：Claude Code
```

## 建議頻率
每月一次，或累積入庫十篇左右時做一次。
